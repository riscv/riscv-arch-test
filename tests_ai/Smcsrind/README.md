# Smcsrind and Sscsrind: rule-derived tests for indirect CSR access

One test per `norm:` rule in `src/priv/smcsrind.adoc`, plus the CSRIND rules of `src/priv/smstateen.adoc`
(`mstateen0_csrind_op`, `hstateen0_csrind_op`), which the Smstateen and Ssstateen suites leave to these suites.
Generated by `tests_ai/gen/gen_Smcsrind.py` with helpers in `gen/csrindlib.py`. Machine-level rules (miselect, mireg*,
mstateen0.CSRIND) are in `Smcsrind/`; supervisor- and hypervisor-level rules are in `Sscsrind/`, whose README points
here.

**Which DUTs check these suites.** Sail does not implement Smcsrind/Sscsrind (nor Smaia/Ssaia or Smctr), so its configs
do not select these tests. They run on Spike, Whisper, QEMU and Imperas, which list the extensions in their yamls
although not every run command enables them (see "Subtleties"). With the extensions enabled, Whisper RV64 (and RV32
with the whisper#237 fix) and Imperas pass every file; Spike and Imperas lack Smctr, and the remaining failures are the
model bugs listed at the end.

## How the extensions are tested

- **Modes.** Sscsrind tests boot to S (HS with H) and enter U, VS and VU in trap windows. M-mode parts are
  `<rule>_Sm.S` files that boot to M and require `Sm`. Smcsrind tests boot to M, except those that need S-mode
  windows, which set mstateen0 through T-SBI. CSRs are named by number and MARCH stays `rv${XLEN}i_zicsr_zifencei`.
- **Select registers.** siselect and vsiselect hold every value in 0..0xFFF exactly (edges, 0x55../0xAA.. patterns,
  random), through all eight CSR forms (rs1=x0 and uimm=0 do not write). Outside 0..0xFFF and for miselect, which is
  WARL with an implementation-defined legal set, the tests check what holds for any legal set: a value read back is
  retained when rewritten, csrrw returns it, and a following in-range write reads back exactly (nothing of a custom
  MSB-set value sticks). miselect, siselect and vsiselect are separate registers; VS-mode siselect accesses land in
  vsiselect and leave HS-mode's siselect alone, in both directions.
- **Alias registers.** The behavior at an allocated select value belongs to the owning extension, so the tests check
  only what every range shares: the select register picks the register (writes at one select value do not appear at
  another), the CSR forms behave, and M- and S-mode see the same register. They use Smaia/Ssaia iprio registers at
  0x30, 0x32, 0x34 (valid at both XLENs) and Smctr entries at 0x200-0x204: VS-mode `sireg*` is `vsireg*` selected by
  vsiselect, and from M-mode `vsireg*` and `sireg*` reach the same entry (there is no separate V=1 set). CTR is frozen
  (sctrstatus.FROZEN) and its control registers cleared first, so recorded transfers cannot move the entries. Values
  are WARL, so expectations come from reading the registers back; a hart whose iprio array is read-only zero passes
  those cases trivially.
- **Unimplemented select values.** Reserved values (no extension allocates them) give an UNSPECIFIED access. The tests
  read that as "behaves as a register or raises a CSR-access exception": no trap or illegal-instruction from M/HS,
  plus virtual-instruction from VS. They check xepc, xtval (0 or the instruction bits) and the mode of any trap.
- **Exception causes.** Every alias and select CSR is accessed from U, VS and VU (VS/VU under `H_SUPPORTED`):
  VS/VU direct access to vsiselect/vsireg* and VU access to siselect/sireg* raise virtual-instruction (VU sireg with
  vsiselect swept over reserved, AIA, Smcdeleg, IMSIC and CTR values); U-mode and every access to miselect/mireg*
  from below M raise illegal-instruction.
- **State enables.** mstateen0.CSRIND and hstateen0.CSRIND may be read-only zero or one, so the tests probe that each
  can be set and cleared before checking the gated cases; then they toggle and read back with the other bits
  unchanged. With mstateen0.CSRIND = 0 every access from S, U, VS and VU raises
  illegal-instruction (also the VS/VU cases that are otherwise virtual), M-mode is unaffected, and hstateen0.CSRIND
  is read-only zero. With hstateen0.CSRIND = 0 VS/VU accesses to siselect/sireg* raise virtual-instruction whatever
  vsiselect or the other mstateen0 bits hold, direct VS/VU accesses to vsiselect/vsireg* stay virtual-instruction,
  and HS-mode is unaffected. Transitions back to 1 restore access.
- **Mutation check.** `MUTANTS` in the generator (25 mutants: register widths, merged registers, ignored select
  values, separate V=1 CTR entries, wrong causes, ignored or over-reaching enables, a wrong stateen bit). All are
  caught on whisper-rv64-max with the extensions enabled; `select_ignored_m`/`_s` survive there because Whisper's
  iprio array is read-only zero, and are caught on qemu-rv64-max.

## Rules not tested, or only partly

- `miselect_value_range`: an allocation statement; its observable part is `miselect_op`.
- `Sscsrind_smode_csrs_sz`, `Sscsrind_vsmode_csrs_sz`: widths follow the current XLEN rather than SXLEN/VSXLEN, which
  is observable only when MXLEN differs from SXLEN or HSXLEN from VSXLEN; no configuration allows that.
- The XLEN-change clauses of `miselect_msb_op`, `siselect_msb_op`, `vsiselect_msb_op`: no configuration can change
  MXLEN, SXLEN or VSXLEN.
- `miselect_min_sz`, `miselect_op`, `mireg_access_on_legal_miselect`: shown only with Smaia (0..0x3F must be held,
  per the AIA spec; iprio registers at 0x30-0x3F), the only M-level range a macro reveals; without Smaia they check
  nothing. `sireg_access_on_legal_siselect` likewise
  needs Ssaia, and `vsireg_access_on_legal_vsiselect` needs Ssctr.
- Per-range behavior (iprio fields, IMSIC files, counter delegation, CTR entries) belongs to the Smaia/Ssaia,
  Smcdeleg/Ssccfg and Smctr/Ssctr suites, as do `mstateen0_aia_op`, `hstateen0_aia_op`, `siselect_acc_op`,
  `vsiselect_op`, `hstateen_ctr` and the Ssccfg sireg rules. The stateen encodings (`mstateen0_enc_img`,
  `hstateen0_enc_img`) are in Smstateen/Ssstateen.
- `hypervisor_impl_csrs_access_control`: "any other mstateen bit" is exercised with the other mstateen0 bits only,
  not mstateen1-3.
- Accessibility itself is assumed: the framework sets mstateen0/hstateen0.CSRIND at boot, and tests outside the
  stateen rules expect S/VS-mode access to work. A hart whose CSRIND bits are read-only zero fails them.

## Subtleties

- **Precedence.** With Smstateen, the state-enable section overrides the virtual-instruction rules: mstateen0.CSRIND
  = 0 gives illegal-instruction from VS/VU too, and hstateen0.CSRIND = 0 (with mstateen0.CSRIND = 1) gives
  virtual-instruction "regardless of the value of vsiselect". Directly accessing vsiselect/vsireg* from VS-mode is
  virtual-instruction even though the HS-qualified rule does not apply to these CSRs
  ([#2070](https://github.com/riscv/riscv-isa-manual/issues/2070)). CSRIND gates only the select and alias CSRs, not
  the indirectly reached state's other controls ([#2210](https://github.com/riscv/riscv-isa-manual/issues/2210)) or
  unrelated CSRs such as scountinhibit ([#3158](https://github.com/riscv/riscv-isa-manual/issues/3158)).
- **Open clarifications.** [#2554](https://github.com/riscv/riscv-isa-manual/issues/2554) (VU sireg with vsiselect
  in 0x40-0x5F and menvcfg.CDE = 0) and [#2668](https://github.com/riscv/riscv-isa-manual/issues/2668) (VU sireg
  with an invalid hstatus.VGEIN) ask whether VU accesses can be illegal-instruction. The tests follow the plain text of
  smcsrind.adoc and smcdeleg.adoc (`Ssccfg_hyp_vs_or_vu_access_vsireg_illegal`): VU access to siselect/sireg* is
  virtual-instruction whatever vsiselect holds. Every DUT run agrees.
- **WARL selects.** How an illegal select value is mapped is up to the implementation
  ([#2032](https://github.com/riscv/riscv-isa-manual/issues/2032)); QEMU keeps only 16 bits. Only miselect is
  declared WARL; the tests treat siselect/vsiselect values outside 0..0xFFF the same way (a write does not trap and
  leaves a legal value), which the spec implies but does not state. Unimplemented values in
  vsiselect make VS-mode sireg* accesses UNSPECIFIED ([#2542](https://github.com/riscv/riscv-isa-manual/issues/2542)).
- **Field modulation.** When mstateen0.CSRIND returns to 1, hstateen0.CSRIND holds an UNSPECIFIED value, so the tests
  set it again before relying on it.
- **Configs.** Imperas needs `--override cpu*/Smcsrind=T` and `cpu*/Smaia=T` (otherwise every select/alias access
  traps); Whisper's ISA string needs `smcsrind_sscsrind` and `smctr_ssctr`; Spike and Imperas have no Smctr, so
  `vsireg_access_on_legal_vsiselect` fails there while their yamls list Ssctr. The shared configs in
  `~/act-wt/ext-cfg` enable what can be enabled.

## Model bugs found by this suite

- **QEMU:** with mstateen0.CSRIND = 0, VS/VU accesses to vsiselect/vsireg* and VU accesses to
  siselect/sireg* raise virtual- instead of illegal-instruction; the stateen check runs after the privilege check
  (the CSRIND counterpart of [qemu#4614](https://gitlab.com/qemu-project/qemu/-/issues/4614), reported there in
  [a comment](https://gitlab.com/qemu-project/qemu/-/work_items/4614#note_4184181856)).
  `Sscsrind_csrs_access_control` fails on both XLENs. On RV32, three more tests fail from the known
  [qemu#4611](https://gitlab.com/qemu-project/qemu/-/issues/4611) (HS-mode loses hstateen0h after the boot).
- **Spike:** with mstateen0.CSRIND = 0, VU-mode sireg* raises virtual- instead of illegal-instruction
  ([riscv-isa-sim#2082](https://github.com/riscv-software-src/riscv-isa-sim/issues/2082), closed but still present on
  master; reopening requested in
  [a comment](https://github.com/riscv-software-src/riscv-isa-sim/issues/2082#issuecomment-6708414832)). The older Spike also raised virtual-instruction for VU-mode mireg
  ([riscv-isa-sim#2501](https://github.com/riscv-software-src/riscv-isa-sim/issues/2501), fixed).
- **Whisper RV32:** the CSRIND checks read mstateen0/hstateen0 without their high halves, so VS-mode siselect/sireg
  trap with hstateen0h.CSRIND = 1, and a VS sireg access with hstateen0.CSRIND = 0 and vsiselect = 0x40 raises
  illegal-instruction ([whisper#237](https://github.com/tenstorrent/whisper/issues/237)); seven tests fail, and all
  pass with the fix in draft PR [whisper#239](https://github.com/tenstorrent/whisper/pull/239).
