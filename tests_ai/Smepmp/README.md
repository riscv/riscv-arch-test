# Smepmp: rule-derived tests for Machine Mode Lockdown (mseccfg.MML)

One test per `norm:` rule about MML: the truth table in `src/priv/smepmp.adoc` and the `mseccfg_mml_*` rules in
`src/priv/machine.adoc`, plus the field-presence rules. The RLB and MMWP rules are in [`../PMP`](../PMP/README.md).
Generated by `tests_ai/gen/gen_Smepmp.py` with `gen/epmplib.py`.

## How the extension is tested

- **One-shot files.** MML is sticky until reset and, once set, M-mode may execute only from M-mode-only or locked
  shared rules with X. Each test boots to M-mode and, while MML=0, gives the image its own rules: the code
  (`rvtest_entry_point` to `scratch`) and `.text.rvmodel` (from `__stack_top` rounded up to 4 KiB, to `_end`) get
  locked R+X TOR rules (entries 3-6), and one 4 KiB code page for S- and U-mode gets an L=0 R+X rule (entry 2; R
  because the M handler reads the trapping instruction there through MPRV). Data has no rule: with MMWP=0, M-mode
  may read and write it by default. Then MML is set, and nothing is restored.
- **Qualification.** A test does nothing unless entries 1-15 are OFF and unlocked, MML = MMWP = 0, entry 15 exists,
  the grain is at most 4 KiB, and TOR and NAPOT are supported. Every test except `mseccfg_fields_exist` also does
  nothing when MML reads 0 after being set; `mseccfg_fields_exist` requires MML to read 1.
- **Accesses.** Test regions are 4 KiB NAPOT pages of `ret` words in the data section, one test entry each. Loads,
  stores (of the page's own word) and fetches (jalr to a `ret`) run in M-mode, and in S- and U-mode inside the S/U
  code page (entered with MRET; the snippet returns through a T-SBI GOTO_MMODE placed in the page's last word, which
  resumes on the next page, M-mode code). Faults must be access faults with xtval 0 or the address (xepc = the target
  for a fetch). M-mode loads with MPRV=1 check that the effective privilege mode decides.
- **Expected outcomes** come from the truth table (`epmplib.TABLE`), and with no matching rule M-mode may load and
  store but not fetch, and S/U-mode is denied.
- **Rules that need an executable L=1 rule** (1001, 1101) write it before MML is set. The shared-code encodings 1010
  and 1011 (RW=01, reserved while MML=0) and the x_restrict lift need RLB: those parts run when RLB can be set before
  any rule is locked; RLB is then kept through the setup and cleared before checking locks.
- **Locks.** For M-mode-only, shared-code and 1111 rules, a write of the entry's pmpcfg byte and pmpaddr is ignored
  with RLB=0. Every pmpcfg write in `mseccfg_mml_x_restrict` is one csrw with the other bytes as read, so ignoring the
  whole write and ignoring only the entry's byte agree.
- **Mutation check.** `MUTANTS` in `gen_Smepmp.py` change the truth table or an expectation; each fails a test on
  Spike RV64 (Sail does not implement Smepmp).

## Rules not tested here, or only partly

- **Other suites (PMP):** `mseccfg_rlb_op_warl`, `mseccfg_mmwp_op_warl`, `pmp_rw01_rsv`; reset values
  (`mseccfg_mml_mmwp_rlb_rst`) are not observable. MML is never combined with MMWP here (MMWP would also need an
  M-mode data rule).
- **Partial:** `mseccfg_mml_shared_l1_op` runs only when RLB can be set. Without RLB, `mml_truth_table` sweeps the
  L=0 rows and the non-executable L=1 rows; the executable L=1 rows are then covered by `mseccfg_mml_m_rule_op` and
  `mseccfg_mml_exec_code` (1001, 1101) only. VS/VU accesses (H) are not tested; PMP treats them as S/U.
- **Not yet generated:** the RLB exception of `mseccfg_mml_m_rule_op` (RLB=1 lets an M-mode-only rule be modified),
  MPRV stores and MPRV with MPP=M, and VS/VU accesses.
- **Layout assumption:** the tests rely on link.ld placing no M-mode-written data (tohost, signature) in the code
  ranges; true for every ACT DUT's link.ld, but not checked at run time.
- **Qualification:** harts with fewer than 16 PMP entries or a grain above 4 KiB run the tests as no-ops.

## Subtleties

- The configurations of Sail, Whisper and Imperas list Smepmp, but MML reads 0 on all three: Sail does not implement
  Smepmp (sail-riscv PRs #196 and #601 are open), ACT's `whisper.json` does not enable `smepmp`, and ACT's
  `imperas.ic` does not set `Smepmp_version`. With `smepmp` added to the Whisper ISA string or
  `--override cpu*/Smepmp_version=1.0` for Imperas, all tests pass. `mseccfg_fields_exist` fails on the three as
  configured; the PMP suite's MMWP/RLB tests pass on them only because their probes find nothing to test.
- The SFENCE.VMA rule for PMP changes also applies to MML ([#1859](https://github.com/riscv/riscv-isa-manual/issues/1859));
  tests with S-mode fence after every PMP and MML change.
