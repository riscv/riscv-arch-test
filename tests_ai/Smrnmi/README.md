# Smrnmi: rule-derived tests

Generated by `gen/gen_Smrnmi.py` (helpers `gen/smrnmilib.py`): one file per rule of `src/priv/smrnmi.adoc`.

## How Smrnmi is tested

- **No RNMI, NMIE = 1.** No ACT configuration has a way to raise an RNMI (there is no `RVMODEL_*` macro for one),
  and software cannot clear `mnstatus.NMIE`, which the framework boot sets (`tests/env/rvtest_setup.h`,
  `SMRNMI_SUPPORTED`). Everything here runs with NMIE = 1: the four CSRs, their WARL rules, the set-only NMIE bit,
  and MNRET. Every test boots to M-mode, names the CSRs by number and emits MNRET as `.word 0x70200073`.
- **MNRET** (`mnret_exist`, `mnret_mode`, `rnmi_resume`, `mnret_restore`, `mnret_mprv`, `mnstatus_mnp*_op`,
  `mnret_Zicfilp`). The common primitive (`smrnmilib.mnret_land`) writes mnepc = L and mnstatus.MNPP/MNPV, points
  mepc at a decoy W just after the MNRET, executes MNRET in a trap window, records the landing PC with
  `auipc x7, 0` at L, then probes the privilege with `csrr mstatus` (no trap in M-mode; illegal-instruction below
  M, whose origin xPP/xPV the window checks). A fall-through or a return through mepc lands at W. Targets are M, S,
  U, VS and VU, each when implemented. Negative dependencies: mstatus.MPP and MPV name a different mode; mstatus
  after MNRET to M-mode equals mstatus before it (except MPRV, SDT and MDT); MNPP and MNPV are unchanged by MNRET.
  MNRET from S (mstatus.TSR = 0 and 1), U, VS (hstatus.VTSR = 0 and 1) and VU raises illegal-instruction, with mnepc
  set so a design that executes it continues without a trap.
- **ELP** (`mnret_Zicfilp`): the MNRET target is an `ebreak` followed by a 4-byte-aligned `lpad 0`. ELP = 1 shows as
  a software-check exception (cause 18) with MPELP = 1 in the handler's saved mstatus; ELP = 0 as a breakpoint with
  MPELP = 0. Each target mode y is run with yLPE x MNPELP and with another mode's LPE bit set instead.
- **CSRs.** `Smrnmi_csrs`: all eight CSR forms in M-mode, illegal-instruction from S, U, VS and VU.
  `mnscratch_sz_acc_op`: arithmetic edges and every CSR form. mnepc: valid addresses are taken from the test's own
  code address L' (bits 10:0 cleared, then bits 10:2 varied: always below 2^bitlen(L)), plus any 32-bit value on
  RV32 with Sv32 and the canonical edges of each RV64 Sv mode the hart supports (probed by writing satp.MODE in
  M-mode; without virtual memory the physical-address width is unknown).
  `mnepc_invalid_convert` (RV64) writes values invalid under every configuration and checks a necessary condition
  on the read-back value (not below 2^bitlen(L), and not Sv39-canonical when Sv39 exists). IALIGN = 16 means
  misa.C = 1 or Zca without C; the misa.C-toggling rules probe a writable misa.C at run time.
- **MPRV** (`mnret_mprv`): after MNRET to S, U, VS or VU, MPRV is read from the mstatus the M-mode handler saved on
  entry to the privilege probe's trap (the trap log). Reading it after returning to M-mode would prove nothing: the
  handler's MRET to the lower mode clears MPRV on its own.
- **NMIE** (`mnstatus_nmie_set_clear`): every write form that would clear NMIE leaves it 1 while the rest of the
  write (MNPP) takes effect, and an M-mode ebreak afterwards still reaches the ordinary M-mode handler.
- **Configurations.** Only the Whisper configurations (and XiangShan) list Smrnmi; Sail does not model it, so the
  suite has no Sail run. It was run on Whisper rv32/rv64 max, m and mu (on PATH and the CI pin 6b8cce1), and on
  scratch copies of the Spike (pin f90d5af with `_smrnmi`, and an rv64 copy without C for `mnepc_ialign32`), QEMU
  (`smrnmi=true`) and Imperas (`rnmi_version=0.4`) max configurations with Smrnmi enabled in the UDB yaml.
- **Mutation check.** `MUTANTS` in `gen_Smrnmi.py` (27 expectation switches). Every mutant fails a test on Whisper
  rv64-max; the RV64-only mutants (`mnscratch_32bit`, `mnepc_32bit`, `mnepc_invalid_to_valid`) are expected to
  survive on rv32.

## Rules not tested

- **Need an RNMI** (no configuration can raise one, and NMIE cannot be cleared to reach the NMIE = 0 state):
  `rnmi_priority`, `rnmi_not_disabled`, `rnmi_entry`, `rnmi_entry_cause`, `rnmi_entry_priv`,
  `rnmi_entry_nmie_clear`, `rnmi_enter_mmode`, `mncause_op`, `mncause_interrupt`, `mncause_interrupt_code`,
  `mncause_interrupt_zero`, `mnstatus_mnpelp_update`, `mnstatus_nmie_enable`, `mnstatus_nmie_disable`,
  `mnstatus_mprv_clear`, `mnstatus_wfi`, `rnmi_exception_nmie0`. The entry halves of `mnepc_sz_acc_op`,
  `mnstatus_mnpp_op`, `mnstatus_mnpv_op` and `mnstatus_mnpelp_op` likewise. The unresumable-NMI rules in
  machine.adoc (`nmi_op`, `nmi_mcause_source`, `nmi_mcause_impl_def`, `nmi_mcause_restrictions`, `nmi_no_rst`)
  need an NMI source too.
- **Reset value** (`mnstatus_nmie_reset`, machine.adoc `mnstatus_nmie_rst`): the framework boot sets NMIE before a
  test runs and keeps no copy of the reset value.
- **Untestable:** `rnmi_trap_addr`, `rnmi_exc_trap_addr` (implementation-defined addresses, used only by an RNMI or
  by an exception with NMIE = 0); `mncause_img`, `mnstatus_img` (field diagrams; every test uses the field
  positions); `mnstatus_reserved` (reserved bits "should" read zero: a recommendation).
- **Smdbltrp/Ssdbltrp suites:** `mncause_doubletrap`, and in machine.adoc `trap_unexp_rnmi`,
  `mstatus_mdt_not_set_rnmi`, `trap_unexp_mnstatus_nmie_0`, `trap_unexp_hndl_rnmi`, `trap_unexp_hndl_no_rnmi`,
  `mstatus_mdt_clr_mnret`, `sstatus_sdt_clr_mnret`, `vsstatus_sdt_clr_mnret`; smdbltrp.adoc
  `Smdbltrp_with_Smrnmi_op`. `rnmi_resume` ignores MDT and SDT when it compares mstatus.

## Subtleties

- MNRET leaves MNPP unchanged ([#1503](https://github.com/riscv/riscv-isa-manual/issues/1503)); unlike MRET, it does
  not write the previous-privilege field. `rnmi_resume` checks MNPP and MNPV after every MNRET.
- An illegal MNPP value (2, or an unimplemented mode) maps to some legal value
  ([#2585](https://github.com/riscv/riscv-isa-manual/issues/2585)); every implemented mode is accepted.
- MNPV exists only with H ([#2899](https://github.com/riscv/riscv-isa-manual/issues/2899)); without H it is a
  reserved bit, which only "should" read zero, so it is not checked. MNRET with MNPP = M and MNPV = 1 must return to
  M-mode.
- MRET is legal in an RNMI handler ([#2240](https://github.com/riscv/riscv-isa-manual/issues/2240)), and MNRET is
  legal with NMIE = 1 (nothing forbids it); the tests rely on the latter.
- MNPELP holds a value whatever mseccfg.MLPE, like MPELP
  ([#3331](https://github.com/riscv/riscv-isa-manual/issues/3331)). QEMU before 8478697ac0 made it read-only zero
  ([qemu#4222](https://gitlab.com/qemu-project/qemu/-/work_items/4222), fixed on master).
- `mnstatus_nmie_set_clear` reads "attempts to clear NMIE have no effect" per field: a csrw with NMIE = 0 still
  writes MNPP. `mnstatus_mnpp_op` infers that MNPP is a writable WARL field from "encoded in the same manner as
  mstatus.MPP"; the spec does not say so in as many words.
- `mnret_Zicfilp` accepts xtval 0 or 2 for the landing-pad software-check, as the Zicfilp suite does; the exact value
  is that suite's rule.
- `mnret_mprv` needs U-mode (MPRV is read-only zero without it). With MPRV = 1 in M-mode, MPP is M whenever memory
  is accessed; the M-target case sets MPP = U only across the MNRET.
- QEMU (scratch config with `smrnmi=true`): mnepc[0] is writable and MNPP holds 2 (both still in master); VS/VU trap
  windows entered by `mret` fail through the known mstatus.MPV bug
  ([qemu#4588](https://gitlab.com/qemu-project/qemu/-/work_items/4588),
  [qemu#4620](https://gitlab.com/qemu-project/qemu/-/issues/4620)).
