# Svinval: rule-derived tests

Generated by `tests_ai/gen/gen_Sv.py`. The shared mechanics are in [../Sv/README.md](../Sv/README.md).

## How the extension is tested

- **Sequences.** SFENCE.W.INVAL / SINVAL.VMA / SFENCE.INVAL.IR sequences replace SFENCE.VMA for each rs1/rs2 form.
  The checks:
  - after the full sequence, the new translation (load, store and fetch);
  - before SFENCE.INVAL.IR, the old or the new one;
  - scoping by VA and ASID, with global mappings exempt from the ASID form;
  - batched SINVAL.VMAs.
- **Store ordering.** PTE stores made before SFENCE.W.INVAL are ordered; stores made after it may not be.
- **Validity.** Each instruction is executed in each mode:
  - U-mode: illegal instruction;
  - mstatus.TVM=1: SINVAL.VMA and HINVAL.GVMA illegal in S/HS-mode; SFENCE.W.INVAL/INVAL.IR unaffected;
  - with H: HINVAL.* virtual in VS/VU-mode, SINVAL.VMA virtual in VU-mode and in VS-mode with hstatus.VTVM=1,
    SFENCE.W.INVAL/INVAL.IR virtual in VU-mode and permitted in VS-mode with VTVM=1.

## Rules not tested here

- **Two-stage semantics.** `Svinval_hinval_vvma_gvma`, `Svinval_hinval_gvma_uses_vmid`: the fencing effect of HINVAL.*
  on VS-stage and G-stage translations belongs with the H suite's fence tests.

## Subtleties

- **Incomplete sequences.** Without SFENCE.INVAL.IR, each access uses either the old or the new translation, nothing
  else ([#1936](https://github.com/riscv/riscv-isa-manual/issues/1936)).
