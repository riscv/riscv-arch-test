# Zvkb: rule-derived tests

Tests for the `src/unpriv/zvbb.adoc` rules of the instructions Zvkb shares with Zvbb (vandn, vbrev8, vrev8, vrol,
vror), and for the Zve32x dependency rule of the vector crypto chapter
(`Zvkb_Zvkg_Zvkned_Zvknha_Zvksed_Zvksh_Zvks_Zvksc_Zvksg_Zvkt_depZve32x`, which runs on any of those extensions). The
directory requires Zvkb; Zvbb harts also list Zvkb. Generated by `tests_ai/gen/gen_Vzv.py`.

## How the extension is tested

- Same data path as Zvbb (vle/vse, word checks, LMUL=8, vl <= 8, SEW=64 under `#if ZVE64X_SUPPORTED`).
- **vandn.** The complemented operand is vs1/rs1 (asymmetric data; vd = vs1 and vd = vs2 aliasing; vs1 = vs2).
  `vandn-vx_rs1` uses vs2 = all ones so vd = ~Op1 shows the scalar: bits above SEW are truncated; at SEW=64 on RV32
  rs1 is sign-extended (bit 31 set and clear); rs1 = x0.
- **Rotates.** Amounts 0, 1, SEW-1, SEW, SEW+1, 2*SEW-1, all ones and high-bit-only amounts (only log2(SEW) bits
  count); rs1 with random upper XLEN bits; vror.vi uimm 0..63 including uimm[5] (the i5 bit) at SEW=64 and amounts
  > = SEW at smaller SEWs.
- **vrev8/vbrev8.** Distinct bytes per element (vrev8 at SEW=8 is the identity), byte-asymmetric bit patterns.

## Rules not tested here

None of the rules owned here is untested.

## Subtleties

- The vector-scalar vandn operand is "sign-extended or truncated" (pseudocode `sext_or_truncate_to_sew`), unlike
  vclmul.vx (see Zvbc).
