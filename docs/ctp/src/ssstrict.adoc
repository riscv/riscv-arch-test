
=== Ssstrict

The Ssstrict extension indicates that executing unimplemented instructions or accessing unimplemented CSR in the standard or reserved encoding spaces raises an illegal instruction exception.

[quote, https://github.com/riscv/riscv-profiles/blob/main/src/rva23-profile.adoc[RVA23 profile Ssstrict definition]]
No non-conforming extensions are present. Attempts to execute unimplemented opcodes
or access unimplemented CSRs in the standard or reserved encoding spaces raises an illegal
instruction exception that results in a contained trap to the supervisor-mode trap handler.

Vector instructions introduce complex register constraints and are tested separately in <<t-SsstrictV-coverpoints,SsstrictV>>.

==== SsstrictSm

RISC-V does not have a ratified equivalent of Ssstrict for machine mode, but this optional test suite checks the behavior of unimplemented instructions and CSRs from machine mode.  It runs the same tests as <<t-SsstrictS-coverpoints,SsstrictS>> but from machine mode.

==== SsstrictS

Attempt to issue all flavors of 32-bit instructions in the standard and reserved spaces and all 16-bit compressed instructions.  Also attempt to access all CSRs in the standard and reserved spaces that should be inaccessible.  Expect illegal instruction trap for unimplemented instructions and CSRs, matching reference model.

According to the RVA23 profile spec, the illegal instruction should be cause a trap to the supervisor trap handler.  However, delegation is the business of the firmware, not the hardware.  These tests only check that a trap occurs and matches the reference model.

On a hart without Zca, the 16-bit encodings in the compressed sweep may be treated as the start of 32-bit instructions, so xtval may hold either the 16-bit parcel or the 32-bit word it begins.  Sail reports the 16-bit parcel.  The tests accept exactly those two values: an xtval that matches the 32-bit word at xepc is reduced to its 16-bit parcel before comparison, and any other value mismatches.
