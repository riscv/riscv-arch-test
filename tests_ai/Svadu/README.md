# Svadu: rule-derived tests

Generated by `tests_ai/gen/gen_Sv.py`. The shared mechanics are in [../Sv/README.md](../Sv/README.md). This suite also
holds the machine.adoc rules that define Svadu's behavior: `menvcfg_adue_op` and `menvcfg_adue_fence`.

## How the extension is tested

- **`menvcfg.ADUE` and `henvcfg.ADUE`.** Both are written and read back. `henvcfg.ADUE` is checked with H, after
  setting `menvcfg.ADUE`.
- **ADUE=1.** Hardware updating is required for S- and U-mode accesses:
  - A is set by every completed access, including through superpage leaves;
  - D is set only by a completed store;
  - a store to a read-only page faults and leaves D=0.
- **ADUE=0.** The same accesses page-fault, and the PTE is unchanged (Svade).
- **ADUE changes.** A change takes effect after SFENCE.VMA x0, x0.

## Rules not tested here

- **G-stage.** The G-stage half of `menvcfg_adue_op` is in tests_ai/H (`henvcfg_adue_op` and the G-stage tests).
- **ADUE read-only 0.** `menvcfg_adue_rdonly0` needs a hart without Svadu (Sm suite).

## Subtleties

- **QEMU rv32.** QEMU rv32 traps on writes to `henvcfgh` (qemu#4611, excluded in `config/qemu/ci.yaml`), which
  affects `Svadu_hypervisor_adue_writable`.
- **Speculative A updates.** A may be set speculatively, so after a faulting store only D is checked.
