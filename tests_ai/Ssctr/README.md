# Ssctr: rule-derived tests for control transfer records (supervisor level)

One test per `norm:` rule in `src/priv/smctr.adoc`, generated by `tests_ai/gen/gen_Smctr.py` with helpers in
`tests_ai/gen/smctrlib.py`. The tests boot to S-mode (HS with H) and need only Ssctr. The M-mode parts of the rules
(mctrctl.M and MTE, traps into M-mode, mstateen0.CTR, LCOFI freeze) are in `tests_ai/Smctr/<rule>_Sm.S`.

**Which DUTs check this suite.** The Sail model does not implement Smctr/Ssctr, so there is no reference run. The
checking DUTs are QEMU 11.1.3 (the ACT CI pin) and Whisper 6b8cce1 with `smcsrind_sscsrind_smctr_ssctr` added to its
isa string. Spike f90d5af and the Imperas model (stock and engineering build) have no CTR, although their ACT yamls
list Smctr/Ssctr; see `~/act-wt/ctr-findings.md` for the configuration gaps. Every failure on QEMU and Whisper is a
DUT bug (list below). With those bugs patched in Whisper, the whole suite passes on RV64 and RV32.

## How the extension is tested

- **Measurement.** CTR records every qualified transfer of an enabled mode, including the test's own branches and the
  trap handlers'. Each measurement stops recording, sets sctrstatus = 0 (WRPTR = 0) and runs SCTRCLR, sets the
  configuration, runs the transfers under test as straight-line code (or one trap window), stops recording, and then
  reads WRPTR (the number of records) and the entries through siselect = 0x200 + logical entry and sireg/sireg2/sireg3.
- **Reset state.** xctrctl reset values are UNSPECIFIED, so every test first writes sctrctl = 0 and (with H)
  vsctrctl = 0. S-level tests cannot reach mctrctl (not in the T-SBI table), so they assume mctrctl.M = 0 and MTE = 0
  for the T-SBI code in M-mode (see "Subtleties").
- **Trap windows.** Traps into an enabled mode also record the framework handler's transfers (about 20). These tests
  first select the largest supported depth (DEPTH written 4, 3, ... until one reads back as written). They check the
  first records after the anchor only when the depth is at least 64. With a smaller depth they check only that logical
  entry 0 is valid. The sret into a window (at `<window>-4`) and the T-SBI ecall out of it are recorded according to
  the same rules, and the expected record lists include them.
- **Optional fields** are probed at run time and both outcomes are emitted (`TestFile.either`):
  - TYPE (exact types when implemented, else 0);
  - STE (and vsctrctl.STE), RASEMU, every filter bit, NTBREN, EXCINH/INTRINH;
  - MISP and the CCV/CC bits;
  - the supported DEPTH values.
    Filter bits are bits 47:32, so their tests are RV64-only. Writing a probed field alone must read back exactly as the
    probe found it.
- **Privilege-mode tables.** Every cell of the trap and trap-return tables is covered for S/U and for the virtualization
  transitions HS<->VS/VU, plus VS->VU sret. On V transitions, the enables come from sctrctl.S and vsctrctl.S/U.
  The filters and freeze bits come from the register the spec names: filters from vsctrctl, BPFRZ from sctrctl for
  VS/VU->HS, and from vsctrctl for traps to VS.
- **External traps.** Each row of the table is swept over its enables, with the intervening mode's enable both set and
  clear. External traps ignore EXCINH/INTRINH and RASEMU drops them.
- **Cycle counting** (Zicntr for the cycle CSR) is checked only on records with CCV = 1. CC is decoded and compared
  with cycle-CSR brackets around the two records, less the encoding's granularity, and less a frozen interval when one
  is placed between them. Gaps of 50 to 9000 straight-line nops exercise CCE = 0 and CCE > 0.
- **Entry registers, depth and stack.** Entries are filled by software and by recording. Push-down, loss of the oldest
  entry, WRPTR wrap, read-only zero entries beyond the depth, and SCTRCLR are each checked at the smallest and the
  largest supported depth.
- **Mutation check.** `MUTANTS` in `gen_Smctr.py` lists 98 expectation switches, and every one is caught. 88 are
  caught on QEMU rv64 (11.1.3). The other 10 are caught on Whisper rv64 with its sret bug patched: their tests either
  fail on QEMU because of the QEMU bugs below, or need cycle counting.

## Rules not tested, or only partly

- **Not reachable:**
  - `debug_recording_inhibited`: needs Debug Mode (Sdext), which the framework cannot enter.
  - The "XLEN < MXLEN" zero-extension sentences of `Ssctr_ctrsource_sz_acc_op` and `ctrtarget_sz_acc`: the tests run
    with XLEN = MXLEN.
- **RV32:** CTR "does not fully support RV32". xctrctl bits 63:32 (filters, NTBREN, Custom) cannot be written on RV32,
  so their tests are RV64-only. The RV32 recording tests assume those bits reset to 0.
- **Partial:**
  - `ctrtarget_misp`: which transfers were mispredicted is not observable. The test only checks that MISP stays 0 when
    it is not implemented.
  - `ctr_ccounter_sat`: saturation is reachable within 100k instructions only with at most one CCE bit (maximum 8191
    cycles). With more CCE bits only the bracket check applies.
  - `ctr_ccounter_cce_rdonly0` and `ctr_ccounter_impl` assume implemented CC/CCV bits are writable through sireg3
    (the entry registers are read/write inside the depth).
  - `ctr_ttype9/11/13`: CM.JALT, CM.JT and CM.POPRET(Z) (Zcmt/Zcmp) are not generated; JAL/JALR and the C forms are.
- **Not checked by any available DUT:**
  - All cycle-counting checks are vacuous on QEMU, whose records have CCV = 0. Only Whisper checks them.
  - `vsctrctl_lcofifrz_op_Sm` needs hideleg[13] writable (Shlcofideleg), which neither QEMU nor Whisper has.
- **Elsewhere:** the M-level halves of rules are in `tests_ai/Smctr/`. siselect/vsiselect themselves are in
  Sscsrind.

## Subtleties

- **Not-taken branches.** ctrtarget of a not-taken branch is the next sequential instruction (riscv-isa-manual#2349:
  "The target should be the PC of the next sequential instruction").
- **miselect 0x200..0x2FF** are not CTR entries ([#2185](https://github.com/riscv/riscv-isa-manual/issues/2185):
  reserved for M-level, "handled as spec'ed in general for accesses to reserved indices"). The tests use only
  siselect/vsiselect.
- **WARL depth.** An unsupported DEPTH write may keep the previous value. So "write 4" does not select the largest
  depth, and writing the same value twice may read back differently. The tests search for a supported encoding and
  require stability only for supported ones.
- **Freeze** on a breakpoint or LCOFI does not depend on the target mode being enabled for recording. The breakpoint
  or LCOFI itself is never recorded.
- **Compressed forms** are assembled under `.option arch, +c` inside `#if defined(ZCA_SUPPORTED)`, so MARCH stays
  `rv${XLEN}i_zicsr_zifencei` and the 4-byte layout of the other cases does not change.
- **Framework.** The boot code writes mstateen0.CTR = 1 but never touches mctrctl. A hart with mctrctl.M = 1 or
  MTE = 1 at reset would record the T-SBI code and its ecalls. The S-level tests cannot clear it.

## Model bugs found by this suite

- **Whisper** (reproducers in `~/repros/`):
  - On an sret from HS-mode into VS/VU-mode, whether the HS source mode is enabled is decided from vsctrctl.S instead
    of sctrctl.S. `ctrRecordingEnabled` reads SCTRCTL with `peekCsr` after V is set, and SCTRCTL maps to VSCTRCTL then.
    This fails 14 Ssctr and 3 Smctr tests on both XLENs ([whisper#241](https://github.com/tenstorrent/whisper/issues/241), fix in [whisper#245](https://github.com/tenstorrent/whisper/pull/245);
    `2026-11-07-whisper-ctr-sret-hs-to-vs.tar.gz`).
  - RV32: VS-mode sctrdepth raises illegal-instruction instead of virtual-instruction, and vsireg CTR accesses trap.
    This is [whisper#237](https://github.com/tenstorrent/whisper/issues/237) (high halves of mstateen0h/hstateen0h
    are lost), fixed by draft PR [whisper#239](https://github.com/tenstorrent/whisper/pull/239) (`2026-11-07-whisper-rv32-ctr-stateen-high.tar.gz`).
- **QEMU, new** ([qemu#4834](https://gitlab.com/qemu-project/qemu/-/work_items/4834); `2026-11-07-qemu-ctr-sireg-stateen.tar.gz`): sireg*/vsireg* accesses with siselect in 0x200..0x2FF
  ignore mstateen0.CTR and hstateen0.CTR (`hstateen_vs`, `mstateen_ctr0_except_indirect_access_Sm`).
- **QEMU, already reported:**
  - [qemu#4433](https://gitlab.com/qemu-project/qemu/-/work_items/4433): VS external traps require vsctrctl.STE
    (`exttrap_vshs`, `exttrap_ctrtarget0`, `exttrap_vsm_Sm`, `exttrap_requirements_Sm`).
  - [qemu#4434](https://gitlab.com/qemu-project/qemu/-/work_items/4434): V-transition traps use mctrctl filters
    (`ctr_behavior_criteria_transfer_type`).
  - RV32: [qemu#4611](https://gitlab.com/qemu-project/qemu/-/work_items/4611) (hstateen0h SE0 cleared) and
    [qemu#4723](https://gitlab.com/qemu-project/qemu/-/work_items/4723) (overflows lost).
