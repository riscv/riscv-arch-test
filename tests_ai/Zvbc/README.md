# Zvbc: rule-derived tests

One test per `norm:` rule of `src/unpriv/zvbc.adoc`. Tests require Zve64x and Zvbc. Generated by
`tests_ai/gen/gen_Vzv.py`.

## How the extension is tested

- `vclmul_op`, `vclmulh_op`: .vv and .vx at SEW=64 on edge operands (0, 1, MSB, all ones, 0x55.., 0xAA.., random)
  against random multipliers, so every product bit position is exercised; vd = vs1 aliasing.
- `Zvbc_sew64only`: all four instructions at SEW=64 with LMUL=1, 2, 4 and 8.
- `Zvbc_dependent_Zve64x`: the Zve64x features (SEW up to 64 legal at LMUL=1, VLEN >= 64, vadd at SEW=64).

## Rules not tested here

- `vclmul_sewn64_rsv`, `vclmulh_sewn64_rsv`: SEW other than 64 is reserved (no mandated outcome).

## Subtleties

- vclmul.vx/vclmulh.vx on RV32: the text says "the 64-bit value from integer register rs1"; the pseudocode uses
  `zext_or_truncate_to_sew(X(rs1))` (zero-extension), while vector-scalar integer operands are normally
  sign-extended. With rs1 bit 31 set the test accepts either the zero- or the sign-extended operand (a predicate over
  both result words); with bit 31 clear both readings agree and the value is checked exactly. No riscv-isa-manual
  issue was found on this.
