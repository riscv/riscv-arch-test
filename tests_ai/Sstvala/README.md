# Sstvala: rule-derived tests for stval holding the faulting address or instruction

One test per `norm:` rule in `src/priv/sstvala.adoc`, plus `stval_faulting_address_variable_instr` from
`supervisor.adoc`. That rule constrains only a nonzero stval, and Sstvala makes stval nonzero, so it gets its test
here. Generated by `tests_ai/gen/gen_Sx.py`. Mutants are named `Sx:tval_*`.

## How the extension is tested

- **Strict values.** Without Sstvala, stval may be 0 for every one of these traps, and the base suites accept 0.
  Here only the defined value is accepted:
  - the exact faulting virtual address, including byte offsets;
  - the encoding, zero-extended, for illegal- and virtual-instruction exceptions;
  - the page boundary when a misaligned access or a 32-bit instruction faults in its second page.
- **Free outcomes.** These stay free: whether a misaligned access traps, and whether it raises the misaligned or the
  access-fault cause. Each accepted cause gets its own stval check: the access's address for the misaligned cause,
  and any address inside the access for an access fault (the hart may split the access, and stval is then the
  address of the portion that faulted).
- **Faults.**
  - Misaligned loads, stores, LR and AMOs, in Bare mode.
  - Access faults at the configuration's address for each kind (`RVMODEL_ACCESS_FAULT_ADDRESS_LOAD`, `_STORE`,
    `_FETCH`). It is 0 on most configurations, so a page is also mapped onto it: the access fault then reports a
    nonzero virtual address.
  - Page faults on loads, stores, AMOs, LR and fetches, and misaligned accesses into or out of an invalid page.
    These use Sv39 or Sv32, probed, from S and U.
  - Instruction-address-misaligned on harts without C.
  - VS-mode traps taken in HS-mode, with H.
  - Sdtrig mcontrol6 execute and load-address triggers with action 0, programmed through T-SBI. They run only if
    tdata1 holds the trigger.
- **Instructions.** Privileged instructions and CSR accesses beyond the current mode, writes to a read-only CSR, and
  SFENCE.VMA with TVM=1 (when TVM can be set; it may be read-only 0) are used from S and U. With C and D, C.FLDSP with FS=Off is used. With H, VS/VU
  virtual-instruction and illegal-instruction exceptions are taken in HS-mode.

## Rules not tested here

- Breakpoints from triggers other than mcontrol6 execute and load-address triggers. Only those two are programmed.
- Hardware-error exceptions in `stval_faulting_address_variable_instr` cannot be raised on demand.

## Subtleties

- **Misaligned accesses across pages.** If a misaligned access into a faulting page raises a page fault, stval is
  the address of the portion that faulted (`stval_op_load_store_fault`). That is the page boundary when the second
  page faults, and the access's own address when the first page faults.
- **Instructions fetched in parts.** For a 32-bit instruction whose second half faults, sepc is the instruction and
  stval is the page boundary (`stval_faulting_address_variable_instr`).
- **Invisible trap handler.** On configurations that use the framework's invisible trap handler, an S-mode
  illegal instruction goes through M-mode first. M-mode then writes stval itself (`UDB_REPORT_ENCODING_IN_STVAL_ON_*`),
  so those cases test the framework there, not the hart.
- **LR.** A misaligned LR.W is accepted only as 4 or 5. Zalrsc says "an address-misaligned exception or an
  access-fault exception" without naming the kind, and LR is a load.
- **Trigger stval.** Sdtrig says the stval of an mcontrol6 trigger is "the address being accessed and which caused
  that trigger to fire" (`Sdtrig_mcontrol6_faulting_address`). For a load, the test checks stval only, not sepc,
  because the trigger may fire before or after the load.
