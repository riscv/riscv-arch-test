# Zvkned (AES): rule-derived tests

One test per `norm:` rule of `src/unpriv/zvk.adoc` for Zvkned, plus the cross-cutting vector crypto rules
(`veccrypto_*`) applied to Zvkned's instructions. Generated by `tests_ai/gen/gen_Vzv.py` (reference functions in
`gen/vzvlib.py`).

## How the extension is tested

- **Data path.** Element groups are `.word` arrays loaded with `vle<SEW>.v` into vd = v8, vs2 = v16 and vs1 = v24
  (LMUL=8; cases that need more elements than VLEN=32 holds at LMUL=8, such as two 256-bit SM3 or SHA-512 groups
  or three groups, run only when vlenb shows a large enough VLEN); `.vs` forms take the scalar element group from v16 followed by a
  decoy group, which must not be used. Results are stored with `vse<SEW>.v` and checked word by word.
- **Known answers.** FIPS-197 Appendix C.1/C.3 round states (AES-128 and AES-256) for vaesef, vaesem, vaesdf, vaesdm and vaesz; FIPS-197 A.1/A.3 key expansions for vaeskf1/vaeskf2. The generator's reference functions follow the operation pseudocode in
  `zvk.adoc` and reproduce those standard vectors when chained (checked offline), so expected values do not come
  from a model.
- **Element-group control** (in every element-group directory):
  - `<ext>_vl` and `veccrypto_vl_vstart_egsconstr`: vl = EGS processes group 0 only (group 1, in the tail, stays
    undisturbed with tu), vl = 0 writes nothing, vl = 2*EGS processes both.
  - `<ext>_vstart`: vstart = EGS with vl = 2*EGS for each instruction. The instruction may raise illegal-instruction
    for a nonzero vstart (`vstart_vtype_dep`); if it runs, group 0 (prestart) is undisturbed, group 1 is processed
    and vstart reads 0; if it traps, vstart and vd are unchanged and xtval is 0 or the instruction bits.
  - `veccrypto_lmul_egwconstr`: vl = 0 at every LMUL from mf8 to m8; illegal-instruction exactly when vtype is vill
    or LMUL*VLEN < EGW, computed from vlenb at run time.
  - `veccrypto_eeweqsew` and the `*_egw*` rule: two groups of EGS SEW-wide elements per instruction at vl = 2*EGS,
    a third group left undisturbed.
- **Mutation check.** `gen_Vzv.py`'s `MUTANTS` (`Vzv:<mutant>`) model wrong round functions, wrong immediate
  handling and wrong vl/vstart/EGW/.vs control; each fails a test on Sail (the EGW mutant on a VLEN=128 Sail
  configuration, where mf2 is legal but LMUL*VLEN < EGW).
- **Round functions.** `*_ops` use an all-zero round key so the S-box/ShiftRows/MixColumns steps show alone
  (states with 16 distinct bytes catch a wrong row shift); `*_xor_form` checks the key source (.vv per group, .vs
  one key for every group); `vaesdm_invmix` checks that InvMixColumns follows AddRoundKey.
- **Key schedule.** `vaeskf1_*`/`vaeskf2_*`: every round, word chaining with single-word inputs, uimm[4] ignored,
  out-of-range rounds mapped by inverting uimm[3] (0, 11-15 for vaeskf1; 0, 1, 15 for vaeskf2), odd/even round
  functions and Rcon.
- **Vector-scalar.** `veccrypto_vsins_vs2` uses vs2 = v16, vs2 = v4 (aligned to 4, not to the LMUL of 8) and, when
  VLEN >= 128, vs2 = v3 at LMUL=8 and LMUL=1: the scalar element group has EMUL = ceil(128/VLEN), independent of
  LMUL. `veccrypto_vsins_vd` and `veccrypto_vsins_vs2function` check that vd is the state source and destination
  and that one key is applied to 2 and 4 groups.

## Rules not tested here

- Reserved encodings and configurations (no mandated outcome): none of Zvkned's own, `veccrypto_vl_vstart_rsv` (vl or vstart not a
  multiple of EGS) and `veccrypto_sew_rsv`.
- Timing: `Zvkned_dataindeptiming`, `zvk_dataindep_timing` (data-independent latency is not observable by a functional test).
- `veccrypto_vsins_vdvs2overlap` (vd overlapping the scalar group) is reserved; `veccrypto_indepZkt` states that
  the instructions do not need Zkt, which has no observable consequence.

## Subtleties

- VLEN, ELEN and LMUL support are read at run time: EGW cases with fractional LMUL are illegal at VLEN=128 but legal
  at VLEN=1024 (mf2 with SEW=32), and vill LMULs must trap too.
- [sail-riscv#2074](https://github.com/riscv/sail-riscv/issues/2074) (open): Sail checks the `.vs` vs2 operand
  against LMUL alignment and overlap, so `vaes*.vs v8, v4` at LMUL=8 raises illegal-instruction and
  `veccrypto_vsins_vs2` fails on Sail. The other tests use an LMUL-aligned vs2 so that they do not depend on it.
- [riscv-isa-manual#2612](https://github.com/riscv/riscv-isa-manual/issues/2612): the `.vs` scalar element group
  has its own EMUL (e.g. v12-v13 for VLEN=64) and is broadcast to every vd group; vaeskf1/vaeskf2 are not
  vector-scalar (vs2 is a vector of element groups).
- The engineering Imperas build processes the prestart group of `.vs` instructions (vaesem.vs, vsm4r.vs) when
  vstart = 4, so `Zvkned_vstart` fails there (not yet reported upstream). The `.vv` forms are correct.
- Spike raises illegal-instruction for a nonzero vstart on these instructions, which `vstart_vtype_dep` permits.
- vaesz's pseudocode raises illegal-instruction when vstart is not a multiple of EGS; the normative text calls that
  case reserved, so it is not tested.
