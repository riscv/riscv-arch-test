# Svrsw60t59b: rule-derived tests for PTE bits 60-59 reserved for software

One test per `norm:` rule in `src/priv/svrsw60t59b.adoc`. All three are RV64 only and pass trivially on RV32.
Generated by `tests_ai/gen/gen_Sx.py`. Mutants: `Sx:rsw_bits_fault`, `rsv58_ignored`, `ad_clears_rsw` and
`no_sv39`.

## How the extension is tested

- **S-stage.** For Sv39, Sv48 and Sv57 (probed), leaves with bit 59, bit 60 and both must translate:
  - loads, stores and fetches from S-mode, and U-mode loads of U=1 leaves;
  - a 2 MiB leaf, and a pointer PTE with both bits set.
- **Contrast.** Bit 58 stays reserved, so a leaf with it set must raise a page fault.
- **A/D updates.** With Svadu (menvcfg.ADUE settable), a hardware A/D update must leave bits 60-59 set. Without it,
  the access raises a Svade page fault.
- **VS-stage.** With H, VS-stage leaf and pointer PTEs (read for HLV.W) are covered by the first rule.
- **G-stage** (`Svrsw60t59b_H_g_stage_reserved_bits`). Sv39x4, Sv48x4 and Sv57x4 (probed) use leaves, a pointer and
  a 2 MiB leaf with the bits set, read through HLV.W. A G-stage leaf with bit 58 must raise a load guest-page fault.
- **`Svrsw60t59b_depends_on_Sv39`.** satp must accept Sv39 and translate.
