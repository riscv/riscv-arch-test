# S: rule-derived tests for supervisor mode

One test per `norm:` rule in `src/priv/supervisor.adoc`, except the virtual-memory sections (Sv suite) and the rules
that belong to Sstc, H, Sscofpmf, pointer masking, Zicfilp/Zicfiss and Ssdbltrp. The suite also covers the S-mode parts
of supervisor rules in `src/priv/machine.adoc`. It is generated by `tests_ai/gen/gen_S.py`, with helpers in
`tests_ai/gen/slib.py`. Mutants are named `S:<mutant>`.

## How supervisor mode is tested

- **Modes.** Tests boot to S-mode (HS-mode with H). They enter U-mode with SRET (`TestFile.enter`) or a T-SBI GOTO
  (when SPP must stay 1), and they leave U-mode through T-SBI. M-level CSRs (`mstatus`, `mip`, `mcounteren`,
  `menvcfg`) are reached through T-SBI. Some rules need M-mode: `mideleg` views, `misa.C`, `satp` probes, TSR=1 (the
  framework's S-mode handler returns with SRET), and SRET with MPRV=1. These are in `<rule>_Sm.S` files, which boot to
  M-mode and require `Sm`.
- **Traps.** Each trap is checked in the framework trap log:
  - the number of traps, the cause, and xepc;
  - xtval: 0 or the defined datum (instruction bits, faulting address, or the EBREAK address);
  - the mode the trap came from (SPP/MPP), and the logged `sstatus` (SPP, SPIE, SIE).

  Before a trap, the fields it must write are preset to other values (`scause`, `sepc`, `stval`, SPP, SPIE).

- **Interrupts.** Each S-level interrupt is used when its `sie` bit is writable (the hart implements it):
  - SSI, through `sip.SSIP`;
  - STI, through M-mode `mip.STIP` (`menvcfg.STCE`=0);
  - SEI, through the platform hook or `mip.SEIP`.

  The cases sweep mode (S, U), SIE, the `sie` bit, and pending. Several pending interrupts are taken in order, and the
  test reads them back from the trap log. Interrupts enabled by a CSR write or by SRET must trap before the next
  instruction (xepc is checked exactly).

- **stvec modes.** The framework trap entry is a trampoline, and its log records which stub ran. The tests switch
  `stvec.MODE` between Direct and Vectored while keeping the framework BASE. Exceptions must enter stub 0. In Vectored
  mode, interrupt _i_ must enter stub _i_.
- **WARL and optional state.** Optional or WARL state is probed at run time, and both outcomes are emitted
  (`TestFile.either`). This covers UXL=1, UBE, the Direct/Vectored modes, `misa.C`, TSR, `mideleg` bits, CBIE values,
  counter enables, and the illegal-instruction `stval` feature. Expected outcomes use the values read back. For
  bit-wise WARL registers (`sip`, `sie`, `scounteren`, `senvcfg`), the test computes the writable mask W and the
  read-only bits C, and checks each read against `(v & W) | C`.
- **CBO enables.** CBO instructions are `.word` encodings. They operate on a 4 KiB-aligned block that nothing else
  uses. `menvcfg` and `senvcfg` are swept, and the U-mode and S-mode outcomes are computed from the read-back values.
  The U-mode CBO.ZERO result and the CBO.INVAL flush/invalidate result are checked in memory.
- **Mutation check.** `MUTANTS` in `gen_S.py` has 45 expectation switches. Each one fails at least one test on Sail
  RV64.

## Rules not tested here, or only partly

- **Owned by other suites:**
  - Sv: `sstatus_mxr` and `sstatus_sum` (page permissions), `sstatus_ube_implicit_smode` (page-table endianness), and
    `satp` through the Sv sections.
  - Sstc: `stimecmp_stimecmph_sz_acc`, `mip_sip_stip_op`, `menvcfg_stce_zero_op`. This suite covers only the
    STCE=0 behavior of `sip.STIP`.
  - Ssdbltrp/Smdbltrp: `sstatus_sdt*` (8 rules), `*_sdt_clr_mret_sret`, `*_sdt_clr_mnret`, `mstatus_mdt_clr_mret_sret`.
    `menvcfg_dte_sdt_rdonly0` (the read-only-zero case without Ssdbltrp) is tested here.
  - Zicfilp/Zicfiss: `sstatus_spelp`, `senvcfg_lpe_Zicfilp`, `senvcfg_sse_Zicfiss`, `menvcfg_sse_rdonly0`,
    `stval_exception_info`.
  - Pointer masking: `senvcfg_pmm_ssnpm`, `senvcfg_pmm_immediate`, `senvcfg_pmm_enc`.
  - Sscofpmf: `sip_sie_Sscofpmf` (LCOFI).
  - H: `s_interrupt_priority`. The only interrupts for a mode below S are VS-level (H).
  - H: the VS-mode part of `mstatus_tsr_op` (TSR does not affect VS-mode, hypervisor.adoc).
  - Machine-mode suite: the M-only parts of `mstatus_mie_sie_op`, `wfi_unaffected_conditions` (MIE, `mideleg`) and
    `ecall_priv_mode_op` (ECALL from M); `mstatus_tsr_warl`; and the `mip`/`mie`/`msip` rules matched by the
    `sip`/`sie` grep (`mip_msip_*`, `msip_*`, `mip_ssip_*`, `mip_sxip_mie_sxie_rdonly0`).
- **Covered by another test in this suite:**
  - `stvec_img` (the figure) is covered by `stvec`.
  - `mstatus_mie_sie_exist` is covered by `sstatus_sie` and `mstatus_sie_spie_rdonly0`.
  - `sip_acc` permits any bit to be writable or read-only. `sip_sie_warl` and `sip_op` check what it constrains.
- **Not observable:**
  - `senvcfg_fiom`, `senvcfg_fiom_op_atomic` and `senvcfg_fiom_fence_presuc_op` (FENCE and AMO ordering of I/O and
    memory). Seeing them would need a device region and a second observer. The FIOM bit itself is tested
    (`senvcfg`, `senvcfg_fiom_acc_Sm`).
  - `stval_inv_addr_conv` is a permission (invalid addresses may be converted).
  - `supervisor_timer_scheduling`: the facility is the SEE (SBI) or Sstc, and T-SBI has no timer call.
- **Need a fault on part of an access:** `stval_op_load_store_fault` (a misaligned access whose second part faults)
  and `stval_faulting_address_variable_instr` (a fetch fault on the second half of an instruction). These need page
  faults or PMP across a boundary, so they are left to the Sv and PMP suites.
- **Only partly reachable:**
  - `scause_exccode_enc_tbl`: page faults (Sv), counter overflow (Sscofpmf), software check, and the
    S-delegated ECALL from S (the framework takes cause 9 in M-mode) are not produced. Instruction-address-misaligned
    (cause 0) runs only on harts without C.
  - `sstatus_uxl_sz`: the RV32 part (no UXL field) has nothing to observe.
  - `sstatus_uxl_behavior`, `sstatus_uxl_addr_modulo` and `hint_sxlen` run only if UXL can be 1. No configuration in
    CI supports that, so these rules pass trivially there.
  - The UBE tests run only if UBE can be set. No configuration in CI supports that either.

## Subtleties

- **WPRI bits.** WPRI bits that are not furnished must read zero
  ([#2318](https://github.com/riscv/riscv-isa-manual/issues/2318): "Reserved fields MUST be treated as defined" by
  the WPRI definition). `sstatus` and `senvcfg` write ones to every WPRI bit. They never write SPELP, SDT, LPE, SSE
  or PMM.
- **M-only fields in `sstatus`.** After any T-SBI call, the MRET leaves `mstatus.MPIE`=1. `sstatus` bit 7 must still
  read 0.
- **Valid addresses.** `stvec`, `sepc` and `stval` are checked only with addresses inside the test image
  ([#3424](https://github.com/riscv/riscv-isa-manual/issues/3424): "making sure mtval works for the small set of
  known-valid PAs would seem to suffice").
  - `stvec` need not hold invalid addresses ([#1385](https://github.com/riscv/riscv-isa-manual/issues/1385)).
  - In Direct mode, `stvec_op` requires every 4-byte-aligned valid address. Other modes may add alignment, so their
    BASE is not checked.
- **CBIE.** CBIE is WARL, and an implementation may support any subset of 00/01/11
  ([#2245](https://github.com/riscv/riscv-isa-manual/issues/2245)). The tests accept any legal read-back and use it.
  CBO.INVAL may always flush ([#2239](https://github.com/riscv/riscv-isa-manual/issues/2239)), so after an
  invalidate both the new and the old data are accepted. After a flush, only the new data is.
- **WFI in U-mode.** With S-mode, U-mode WFI raises illegal-instruction unless it completes within a bounded time,
  whatever TW is ([#2463](https://github.com/riscv/riscv-isa-manual/issues/2463)). It may not wait forever.
- **`scounteren` width.** `scounteren` is a 32-bit register. The test expects RV64 reads to return 0 in bits 63:32. No
  rule states this directly.
- **Illegal 16-bit instructions.** Reserved 16-bit encodings are UNSPECIFIED without Ssstrict. So the 16-bit
  `stval` cases use C.FLDSP and C.FSDSP with `sstatus.FS`=Off (C and D), which must trap.
- **`stvec` reserved MODE.** MODE values of 2 or more are reserved, and only BASE is stated to be WARL, so writes of
  2 and 3 are not tested.
- **CBIE read back as 00.** A write of 01 or 11 may read back 00 (WARL). U-mode CBO.INVAL must then trap, and
  `cbo-inval_s_mode_enabled_op` expects that.
- **Smaia `mvien`.** `mvien` has no reset value, so `sip_sie_Sm` clears it under Smaia. With `mvien[1]`=1,
  `sip.SSIP` would be writable without `mideleg`.
- **Interrupt timing.** After SRET or a CSR write, xepc must be the next instruction (or the SRET target). Raising and
  lowering an interrupt is awaited with bounded polls of `sip`.
- **Priv-v1.12 rules.** Some rules first appear in Priv-v1.12 (priv preface, changes since 1.11), so their tests run
  only with `S1P12P0_OR_LATER_SUPPORTED` (or `SM1P12P0_OR_LATER_SUPPORTED` for an M-mode rule):
  `sie_sip_strap_time_constraint` (interrupts evaluated immediately after a CSR write or SRET),
  `scause_exception_code_sz` (bits 4-0 required; `scause_exception_code_acc` writes codes 18 and 19 and, without
  Sscofpmf, interrupt 13 only from 1.12, since the WLRL field held only supported codes before), and
  `mstatus_mprv_clr_mret_sret_less_priv_Sm` (SRET clears MPRV).
- **Framework state.** The trap log holds 4 entries. The priority tests take up to 3 traps per window.
  `stvec_sz_base` and `stvec_mode_enc` take traps with `stvec.MODE` changed, since a mode can only be checked by
  taking a trap. They keep the framework BASE and restore `stvec` at the end. Every other `stvec` and `sscratch`
  write is restored before any trap.
- **Known DUT bugs:**
  - QEMU stores the reserved CBIE value 10 ([QEMU #4216](https://gitlab.com/qemu-project/qemu/-/issues/4216)):
    `senvcfg_cbie_rsv` fails.
  - On QEMU RV32, S-mode `senvcfg` accesses trap after the boot writes `mstateen0`
    ([QEMU #4611](https://gitlab.com/qemu-project/qemu/-/issues/4611)). The `senvcfg*` and CBO tests fail there.

  Both are already excluded or noted in `config/qemu/ci.yaml`.

- **Imperas configuration.** `imperas-rv64-max` and `imperas-rv32gck` list Smaia in their yaml, but `imperas.ic`
  does not enable AIA. The `mvien` write in `sip_sie_Sm` raises illegal-instruction there, so that test fails.
