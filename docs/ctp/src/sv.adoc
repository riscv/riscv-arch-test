
=== Sv* Virtual Memory

==== Sv Virtual Memory

The Sv suite has one covergroup and test plan per group: the base `Sv` group, then `Sm`, `Zicbo` and the `Exceptions` groups.
The UDB configuration file determines whether to run tests for Sv32, or for Sv39 and possibly Sv48 and Sv57.

Coverpoints that need M-mode state (`mstatus.MPRV`, `mstatus.TVM`, `mstatus.SBE`, or an M-mode CSR access)
are in the `Sm` groups.
The PMP suites (SvPMP, SvPMPZicbo, SvaduPMP) boot to M-mode because they program PMP entries.

===== Sv_Sm Virtual Memory with M-mode State

The `Sm` group runs only on configurations with `Sm`, so it is not part of a certificate without `Sm`, such as RVA23.
It covers `mstatus.MPRV` accesses, `mstatus.TVM` trapping of `satp` and `SFENCE.VMA`, `mstatus.SBE` for implicit
page-table accesses, and M-mode access to `satp`. The `mstatus.SBE` tests are generated but not run until a
big-endian configuration is available.

==== Svbare Virtual Memory Off

The Svbare suite has two covergroups: Svbare_cg (S-mode and U-mode) and Svbare_Sm_cg (M-mode with MPRV).
The Svbare_Sm tests require Sm, so they are not part of a certificate without Sm, such as RVA23.
