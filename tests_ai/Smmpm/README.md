# Smmpm: rule-derived tests for mseccfg.PMM and M-mode pointer masking

Generated by `gen/gen_Spm.py` with the other pointer-masking suites; the shared mechanics (WARL read-back, the
reference transformation, tags, xtval rules, mutants) are described in `../Smnpm/README.md`. Every file boots to
M-mode and writes mseccfg.PMM directly.

## How the extension is tested

- `mseccfg_pmm_presence_op`: ld, lw (imm), sd, sw (imm) and amoadd.d with tags, for PMM written 11, 10, 00.
- `mseccfg_pmm_enc`: the WARL encodings, the CSR forms, and the other mseccfg fields (Smepmp, Zkr, Zicfilp) untouched.
- `mseccfg_pmm_rdonly0` (FORBIDDEN Smmpm, also RV32): mseccfg (and mseccfgh) probed, PMM bits stay 0, and a tagged
  M-mode load still faults.
- `smmpm_definition`: mseccfg.PMM masks M-mode only; S and U windows are not masked.
- `pm_ignore_pa`: M-mode addresses are physical, so zero-extended; boundary bits 63, 57, 56, 48 and patterns.
- `pm_apply_explicit`: every class of explicit access (integer loads/stores of every width, AMOs, LR/SC, FP,
  vector, CBO.ZERO).
- `pm_not_apply_implicit`: a jalr to a tagged code address faults and the landing pad does not run.
- `pm_misaligned_equivalence`: misaligned loads and page-crossing loads/stores (A into B); the hart may complete
  them or raise address-misaligned or access fault, as without masking.
- `pm_mxr_exception`: mstatus.MXR=1 does not disable M-mode masking.
- `pm_no_csr_sw`, `pm_warl_unaffected`: mepc/mtval software writes of valid addresses (the image address; negative
  Sv39/48/57 VAs when S and the scheme exist) read back exactly whatever PMM is.

## Rules not tested here

- Virtual-address rules (`pm_ignore_va` etc.) do not apply to M-mode (always Bare); MPRV is in Smnpm.
- `pm_debug_trigger`, `pm_no_trap_vector_mask`: see `../Smnpm/README.md`.

## Subtleties

- QEMU: mseccfg.PMM cannot be cleared once set (it is treated as an Smepmp sticky bit), and a write of 01 is
  stored and aborts QEMU on the next access ([qemu#4818](https://gitlab.com/qemu-project/qemu/-/work_items/4818)).

- MXR is never in effect for M-mode ([#3313](https://github.com/riscv/riscv-isa-manual/issues/3313)).
- Zero versus sign extension of a physical address is observable only when bit XLEN-PMLEN-1 is set, which makes the
  address invalid either way; its xtval may then be any invalid address, so only "faults, and does not report the
  masked address" is checked.
