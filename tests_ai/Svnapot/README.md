# Svnapot: rule-derived tests

Generated by `tests_ai/gen/gen_Sv.py`. The shared mechanics are in [../Sv/README.md](../Sv/README.md). RV64 only, Sv39.

## How the extension is tested

Two naturally aligned 64 KiB blocks of 16 data pages are mapped at a 64 KiB-aligned VA by 16 NAPOT PTEs (N=1,
ppn[3:0]=1000), as software must write them. The tests check:

- **Translation.** Every page of the range reaches the block page with the same index, for loads, stores and a
  fetch. The PPN low bits come from the VPN, not the PTE. With Svadu, the A update keeps ppn[3:0]=1000 in memory.
- **Range bounds.** The range ends at its 64 KiB boundaries.
- **Single-PTE range.** With only PTE 0 written, the other pages read their block page (a cached NAPOT entry) or
  fault.
- **Reserved encodings.** ppn[3:0] patterns other than 1000, and N=1 in superpage leaves and pointers, page-fault
  from S- and U-mode.
- **Fences.** SFENCE.VMA of one page removes every cached NAPOT entry for it. NAPOT entries are per ASID.

## Rules not tested here

- **G-stage.** `Svnapot_hyp_gstage` is a G-stage rule (H suite).

## Subtleties

- **N=1 above level 0.** N=1 is reserved for i >= 1, which covers every non-leaf PTE
  ([#823](https://github.com/riscv/riscv-isa-manual/issues/823)).
- **Inconsistent ranges.** PTEs of one range that disagree give unpredictable results. The tests keep the 16 PTEs
  consistent, except in the single-PTE case, which accepts both legal outcomes.
