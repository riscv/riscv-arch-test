# Smcdeleg and Ssccfg: counter delegation to S-mode

One test per `norm:` rule in `src/priv/smcdeleg.adoc`, plus `menvcfg_cde_op` (machine.adoc) and
`csr_supervisor_access` (smcntrpmf.adoc). Generated by `tests_ai/gen/gen_Smcdeleg.py`, with helpers in
`gen/cntrlib.py`. This README covers both directories:

- `Smcdeleg/` holds the rules about M-level state and require Smcdeleg: `Smcdeleg_*`, `menvcfg_cde_op`,
  `csr_supervisor_access`, and `Ssccfg_lcofi_mvip_mvien`. That last rule is named Ssccfg_ in the spec, but mvip and
  mvien are M-mode CSRs and the rule says "For implementations that support Smcdeleg, Sscofpmf, and Smaia". It is
  placed in `Smcdeleg/` on purpose, so that it requires Smcdeleg (and Sm, Sscofpmf, Smaia).
- `Ssccfg/` holds the other `Ssccfg_*` rules, which require Ssccfg.

**No reference model.** Sail does not implement Smcdeleg/Ssccfg (`config/sail/*-max` comment them out), so the suites
were checked on DUTs only:

- QEMU 11.1.2 (`config/qemu/*-max`, which enables both);
- Whisper 6b8cce1, Spike f90d5af and Imperas, with the extensions enabled in scratch copies of their configs (see
  "Configurations" below).

Whisper rv64 passes every test. Each failure on another DUT is traced to a DUT bug under "Model bugs found", with
the faulty source line identified.

## How it is tested

- **Modes.** Tests boot to S-mode and reach menvcfg, mcounteren, mcountinhibit and mhpmevent/mhpmcounter through
  T-SBI.
  - Rules that the spec states "while the privilege mode is M or S" also get a `<rule>_Sm.S` file that boots to M.
  - The scountinhibit masking rules get `_Sm` files too.
  - `csr_supervisor_access` and `Ssccfg_lcofi_mvip_mvien` boot to M-mode only, because mcyclecfg, mvien and mvip are
    not in the T-SBI table.
  - VS and VU are entered from HS-mode with `sret` under `H_SUPPORTED`.
- **WARL state is read back.**
  - mcounteren: every case reads back what the hart holds and skips the cases whose bit did not take the value.
  - mcountinhibit: the implemented bits (IMPL) are probed by writing all ones.
  - mhpmevent3: MINH is read back before relying on it.
  - mideleg[13]: may be read-only one; the mvip alias case is then skipped.
  - hpmcounters with event 0: may be read-only zero, so they accept the written value or 0.
  - cycle and instret keep counting, so a landed value is "written + less than 2^24".
- **Delegated access.** For cycle, instret and hpmcounter3/4/17/31, sireg and (RV32) sireg4 are checked to alias the
  counter in both directions: a write through sireg lands in the counter, and a counter write shows through sireg.
  - All eight CSR forms of sireg on a delegated hpmcounter3: the old value is returned and the counter holds the
    form's result.
  - sireg2/sireg5 for hpmevent3 (Sscofpmf):
    - S/U xINH bits land;
    - MINH reads 0 and is never written, in both directions;
    - OF can be set and cleared.
  - sireg2/sireg5 for cyclecfg/instretcfg (Smcntrpmf, `csr_supervisor_access`): MINH reads 0, a set MINH survives
    S-mode writes, and a clear MINH cannot be set.
  - scounteren = 0 throughout `Smcdeleg_delegated_access` (negative dependency).
- **Illegal cases.**
  - siselect 0x40, 0x41, 0x42, 0x43, 0x50 and 0x5F are swept over sireg1-6, with all eight forms on the first
    register. The swept cases are:
    - CDE=0;
    - sireg3/sireg6;
    - RV64 sireg4/sireg5;
    - 0x41 with mcounteren.TM=1;
    - single cleared mcounteren bits (0, 2, 3, 17, 31), with the neighbouring counter as a no-trap control;
    - the delegated-to-undelegated transition.
  - Missing-extension cases exist only where the extension is absent. With the extension present, the same access is
    a no-trap control.
- **Hypervisor.**
  - VS/VU access to vsiselect/vsireg*, and VU access to siselect/sireg*, are virtual instruction for CDE=0 and 1 and
    for vsiselect inside and outside 0x40-0x5F.
  - HS/M access to vsireg* in range is illegal.
  - VS access to sireg* is illegal (CDE=0) or virtual (CDE=1), over mcounteren/hcounteren combinations.
  - A VS-mode siselect write lands in vsiselect, not in siselect.
- **scountinhibit.**
  - It is a masked alias: delegated bits read and write mcountinhibit (csrw/csrc/csrrs), and non-delegated bits read
    0 and are not written.
  - The mask is applied on access, not stored: clearing a mcounteren bit hides a set inhibit bit, and setting it
    again shows the bit.
  - Traps: CDE=0 is illegal from every mode (S, U, VS, VU, M); CDE=1 is virtual from VS/VU and illegal from U.
- **scountovf (H + Sscofpmf).** With CDE=1, VS/VU reads raise virtual instruction whatever mcounteren/hcounteren
  hold; HS reads succeed; a CDE=0 VS read is a no-trap control.
- **LCOFI.** mvien/mvip[13] and hvien/hvip[13] are writable. The sip/vsip aliases are checked with
  mideleg/hideleg[13] = 0.
- **Mutation check.** `MUTANTS` in the generator holds 27 mutants. All are caught.
  - 13 were run on qemu-rv64-max, restricted to the 21 tests that pass there.
  - The other 14 target tests that QEMU 11.1.2 fails because of its bugs, so they were run on whisper-rv64-max,
    which passes all 31 tests.

## Rules not tested, or only partly

- `Smcdeleg_Ssccfg_tandem`: a platform requirement. The test only checks that a hart declaring Smcdeleg shows the
  Ssccfg state (scountinhibit, sireg at 0x40).
- `menvcfg_cde_rdonly0` (CDE read-only zero without Smcdeleg) is in the Sm suite.
- `Ssccfg_missing_extension_illegal`: the absent-extension cases (no Zicntr, no Zihpm, no Smcntrpmf, no Sscofpmf)
  run only on harts that lack the extension. No current DUT config lacks Zicntr or Zihpm.
- Event-selector values (mhpmevent bits 55:0) through sireg2 are not written: their legal values are
  implementation-defined (WARL), so only the xINH, MINH and OF bits are checked.
- `Smcdeleg_delegated_access`:
  - cycle/instret aliasing is checked only when both mcounteren.CY and IR are writable.
  - The VU-mode part of `Ssccfg_hyp_vs_or_vu_access_vsireg_illegal` reads all of vsireg1-6 and sireg1-6, but writes
    only siselect.
- scountovf from VU-mode with CDE=0, and the Sscofpmf access rules with CDE=0, belong to the Sscofpmf suite.
- Interaction with mstateen0[60] = 0: the framework keeps CSRIND set. Whether CSRIND also gates scountinhibit is open
  ([#3158](https://github.com/riscv/riscv-isa-manual/issues/3158)); the Smcsrind/Sscsrind suites test CSRIND.

## Subtleties

- **"Appear to be not implemented."** With CDE=0, Smcdeleg and Ssccfg "appear to be not implemented"
  ([#2547](https://github.com/riscv/riscv-isa-manual/issues/2547)).
  - Sscsrind makes accesses at a select value "not implemented at supervisor level" UNSPECIFIED. Smcdeleg instead
    names illegal instruction for M/S with CDE=0 (`Ssccfg_illegal_sireg_cde0`) and for VS with CDE=0
    (`Ssccfg_hyp_vs_access_sireg_conditional`), and the tests follow those explicit rules.
  - `Ssccfg_hyp_m_s_vsireg_illegal` has no CDE qualifier, so it is tested with CDE=0 and CDE=1.
- _*VU-mode sireg* with CDE=0_* is virtual instruction, following the plain text of this rule and smcsrind.adoc
  ("regardless of any other mstateen bits"). [#2554](https://github.com/riscv/riscv-isa-manual/issues/2554) asks
  whether the CDE rule applies to VU and is unanswered.
- **scountinhibit traps** come from [#2087](https://github.com/riscv/riscv-isa-manual/issues/2087):
  - CDE=0 is illegal from M/HS/VS (and VU);
  - CDE=1 is virtual from VS/VU;
  - U-mode is illegal.
    A VU access with CDE=0 is not HS-qualified (HS-mode would trap too), so it is illegal, not virtual.
- **Counters are never delegated to VS** ([#2096](https://github.com/riscv/riscv-isa-manual/issues/2096)), so
  vsireg* in 0x40-0x5F has no counter state, whatever hcounteren holds.
- **MINH through sireg*** is read-only zero for hpmevent (Sscofpmf) and cyclecfg/instretcfg (Smcntrpmf)
  ([#2541](https://github.com/riscv/riscv-isa-manual/issues/2541)). hpmevent is a subset of mhpmevent
  ([#2089](https://github.com/riscv/riscv-isa-manual/issues/2089)).
- **AIA field modulation.** When mvien[13] (hvien[13]) goes from 0 to 1 with mideleg[13] (hideleg[13]) = 0,
  sie[13] (vsie[13]) becomes UNSPECIFIED. The LCOFI tests stay in M/HS-mode, where nothing is taken.
- **Framework state.** RV32 sets CDE through menvcfgh bit 28. mhpmevent3-31 are zero at boot.

## Configurations

The Spike, Whisper and Imperas yamls list Smcdeleg and Ssccfg, but their run commands do not enable them. The yamls
also list Smcsrind/Sscsrind and Smaia, which some run commands lack.

- **Spike**: add `_smcdeleg_ssccfg` to `--isa` in `config/spike/*-max/run_cmd.txt`. The CI pin f90d5af has both.
- **Whisper**: add `smcsrind_sscsrind_smcdeleg_ssccfg` to `"isa"` in `config/whisper/*-max/whisper.json`.
- **Imperas**: add these to `config/imperas/{imperas-rv64-max,imperas-rv32gck,imperas-rv32gcv}/imperas.ic`:
  - `--override cpu*/Smcdeleg=T`
  - `--override cpu*/Smcsrind=T`
  - `--override cpu*/Smaia=T`

  Ssccfg has no separate parameter. Smcntrpmf stays F; it is not in the yamls.

Temporary copies with these changes are in `~/act-wt/ext-cfg/`. The DUT bugs below then need exclusions in each
`config/<dut>/ci.yaml`.

  - `qemu-scountinhibit-nondeleg-write`: an scountinhibit write clears the non-delegated mcountinhibit bits
    ([qemu#4831](https://gitlab.com/qemu-project/qemu/-/work_items/4831)).
  - `qemu-vs-sireg-cde0-virtual`: VS-mode sireg* with vsiselect 0x40-0x5F and CDE=0 raises virtual instead of
    illegal ([qemu#4830](https://gitlab.com/qemu-project/qemu/-/work_items/4830)).
  - `qemu-sireg2-cyclecfg-minh`: on RV64, a sireg2 read of cyclecfg/instretcfg clears mcyclecfg.MINH (`&=`). On
    RV32, sireg5 reads MINH ([qemu#4832](https://gitlab.com/qemu-project/qemu/-/work_items/4832)).
  - `qemu-sireg-counter-rmw`: csrrw through sireg on a delegated counter does not return the old value, and
    csrrs/csrrc with rs1 != x0 raise illegal instruction
    ([qemu#4833](https://gitlab.com/qemu-project/qemu/-/work_items/4833)).
- **QEMU, known issues:**
