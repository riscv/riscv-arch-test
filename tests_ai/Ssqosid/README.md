# Ssqosid: rule-derived tests for the QoS identifiers extension

One test per `norm:` rule in `src/priv/ssqosid.adoc`, plus `mstateen0_srmcfg_op` from `src/priv/smstateen.adoc`.
Generated by `tests_ai/gen/gen_Ssqosid.py`.

## How the extension is tested

- **Boot.** Tests boot to S-mode; mstateen0 (mstateen0h on RV32) is changed through T-SBI. The framework boots with
  mstateen0.SRMCFG = 1 (bit 55, `MSTATEEN0_PRIV114`). The M-mode part of the access rule is a `_Sm` file.
- **Access.** All eight CSR instruction forms on srmcfg (0x181), as `.word` encodings that are also the legal xtval
  values:
  - S-mode with SRMCFG=1: no trap. U-mode: illegal-instruction (srmcfg is an S-level CSR).
  - SRMCFG=0: illegal-instruction in S, U, VS and VU (not virtual-instruction), including the read-only forms; M-mode
    access still works.
  - SRMCFG=1: virtual-instruction in VS and VU.
  - Trapping writes leave srmcfg unchanged, and clearing the gate keeps its value.
- **WARL fields.** RCID and MCID widths are implementation choices, so the values read back are not checked; a value
  read back (a legal value) is kept when written again, and every WPRI bit (15:12, 63:28 or 31:28) reads 0.
- **Gate.** mstateen0.SRMCFG reads back 0 and 1 and gates S-mode access; its neighbors (CTR, P1P13) do not.
- **Mutation check.** `MUTANTS` in `gen_Ssqosid.py`; each fails a test on Sail RV64.

## Rules not tested here

- **Not observable on the hart:** `Ssqosid_rcid_mcid_accompany_requests` and
  `Ssqosid_srmcfg_csr_applies_to_all_modes` (RCID and MCID only tag requests to resource controllers outside the hart;
  `Ssqosid_srmcfg_introduced` checks that a value is one register shared across a U-mode excursion).
- **Other suites:** `mstateen0_enc_img` (Smstateen).

## Subtleties

- srmcfg is gated by mstateen0.SRMCFG (bit 55), which earlier drafts planned to share with other priv-1.13-era
  state ([#1147](https://github.com/riscv/riscv-isa-manual/issues/1147)).
- With SRMCFG=0 the rule makes VS/VU accesses illegal-instruction, not virtual-instruction; with SRMCFG=1 (or without
  Smstateen) they are virtual-instruction.
- WPRI fields that an implementation does not furnish are read-only zero, so the WPRI check holds whatever the
  RCID/MCID widths.
