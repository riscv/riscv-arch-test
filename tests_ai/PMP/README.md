# PMP: rule-derived tests for Physical Memory Protection

One test per `norm:` rule of the PMP section of `src/priv/machine.adoc`, plus the rules whose effect is only visible
through PMP (MPRV, MXR/SUM versus access faults, the misaligned-portion mtval, the variable-length fetch
xepc/xtval) and the Smepmp `mseccfg` fields. Generated by `tests_ai/gen/gen_Sm.py` through `gen/pmplib.py`; the
rest of the machine level is in [`../Sm`](../Sm/README.md).

## How PMP is tested

- **Setup.** Tests boot to M-mode. The framework's entry 0 (S/U access to everything, TOR or NAPOT RWX) is saved
  and copied to entry 7, the lowest-priority background (entry 6 is OFF with pmpaddr6 = 0, its TOR base); entries
  0-5 are the entries under test. Everything is restored at the end, with SFENCE.VMA on S-mode harts. Regions are
  pages of a 16 KiB-aligned buffer filled with `ret`, so loads, stores and fetches (a jalr to a `ret`) can hit any
  word. Stores write the word's own value.
- **Probing.** The PMP CSRs are first read in a trap window (a hart with no entries may not implement them). The grain
  is probed on entry 7: with A = OFF, all ones reads back r and z = (r ^ (r - 1)) >> 1 = 2^G - 1. Tests needing
  4 KiB regions run when entry 7 is implemented, U-mode exists and G <= 10; NA4, 8-byte NAPOT and partial-match cases
  need G = 0; TOR cases need TOR (probed on entry 5).
- **Expected outcomes** come from a reference model of the matching rules in `pmplib.model()`: the lowest-numbered
  entry that matches any byte decides; a partial match fails; M-mode passes an unlocked entry; no match fails S/U
  only. Mutants change the model (highest entry wins, partial match allowed, TOR top inclusive, half-size NAPOT,
  M-mode enforced, locks ignored, ...).
- **Coverage.** Every legal R/W/X combination for lw/lr.w, sw/amoadd.w and fetch from M, S and U; OFF, TOR (with
  and without base 0), NA4 and NAPOT from 8 bytes to 16 KiB at their boundaries; priority; partial matches (RV64
  ld/sd over an NA4 entry); no-match; MPRV with MPP = U/S/M (and fetch unaffected); MXR/SUM; misaligned accesses
  and a 32-bit instruction straddling a permission boundary; precise faults (memory and rd unchanged); CBO
  permissions; pmpaddr read masks per grain and retention of pmpaddr[G-1]; NA4 with G >= 1; RW = 01; the RV32/RV64
  pmpcfg layout for entries 8-15; locking (cfg and address protection, TOR base, M-mode enforcement); Smepmp RLB
  and MMWP.
- **Locks and sticky bits** (L, RLB, MMWP) are set only at the end of a test; the restored entry 0 matches every
  address first, so the end-of-test code is unaffected.

## Rules not tested, or only partly

- **Other suites:** `pmp_check_pagetable_access`, `pmp_with_paging`, `pmp_speculative_translations` (Sv/paging).
- **Not observable or permissive:** `pmp_granularity`, `pmp_mmode_only_regions`, `pmp_entry_structure`,
  `pmp_addr_registers`, `pmp_a_field_encoding` (definitions, exercised by every test), `pmp_csrs_warl_access`
  (fields may be read-only zero), `pmp_entry_count` (implemented entries may have read-only-zero fields, so the
  count cannot be measured), `pmp_sfence_required` (a missing fence may still behave correctly),
  `pmp_a_l_rst`, `mseccfg_mml_mmwp_rlb_rst`, `mseccfg_useed_sseed_rst` (the platform may mandate other reset values).
- **VS/VU** (H) behavior of PMP is in the H suite.
- **Not yet generated:** Smepmp MML (`mseccfg_mml_*`, `mml_truth_table`, `mseccfg_fields_exist`): setting MML is
  permanent and makes M-mode lose execute access to every region without a locked M-mode rule, which needs the
  framework's code and data split into separate locked regions.
- **Partial:** `pmp_misaligned_access_behavior`: that the access cannot complete (misaligned or access fault, with
  the legal xtval for each) and that the denied part of a store is not written; misaligned fetches are in
  `mtval_varlen_wr`/`mepc_varlen_wr`. `pmp_full_match_required`, NA4 and 8-byte NAPOT cases run only with G = 0. `pmp_cbm_fault`: an
  execute-only region accepts either outcome (UNSPECIFIED in cmo.adoc).

## Subtleties

- pmpaddr[G-1] is part of the stored value even when written with A = OFF or TOR (it only reads as 0 there), so a
  NAPOT read after writing all ones returns r | z, not r | (z >> 1).
- With G >= 1, NA4 is not selectable and A reads back as some other legal value
  ([#1100](https://github.com/riscv/riscv-isa-manual/issues/1100)).
- The access fault of a misaligned access whose second part is denied reports "the portion of the access that caused
  the fault": the second part's address when the access is split, the access address when it is performed undivided
  (QEMU and Imperas do the latter), or 0. A fetch fault on the second half of a 32-bit instruction reports xepc = the
  instruction and xtval = 0 or the second half's address.
- Every PMP test first checks that entries 1-7 are OFF and no entry is locked; otherwise it does nothing.
- A cache-block management instruction is permitted when a load or a store would be; with only execute permission the
  outcome is UNSPECIFIED (cmo.adoc `cbm_access`).
- With Smepmp, mseccfg.RLB must be 0 for the lock tests (its reset value); a hart with RLB = 1 runs them as no-ops.
