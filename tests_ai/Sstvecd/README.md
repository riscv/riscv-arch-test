# Sstvecd: rule-derived tests for stvec Direct mode

One test per `norm:` rule in `src/priv/sstvecd.adoc`. Generated by `tests_ai/gen/gen_Sx.py` (helpers in
`tests_ai/gen/sxlib.py`), which also writes Shvstvecd and the other small privileged suites. Mutants are named
`Sx:<mutant>`.

## How the extension is tested

- **Where a trap lands.** The framework's S-mode trap entry (`Strampoline`) is a spreader of one 4-byte jump per
  entry, each to its own stub, and the trap log records which stub ran. The tests write `stvec = Strampoline + 4k`
  with MODE=Direct and take traps, which must run entry k. That shows the hart used every BASE bit (2-6) and added
  no cause offset.
- **Trap sources.** ebreak from S and U (delegated by the framework's medeleg[3]), ebreak from VS with H (taken in
  HS-mode), and a supervisor software interrupt raised through `sip.SSIP`.
- **MODE.** Direct must read back exactly, before and after a Vectored write. If Vectored is held, the software
  interrupt enters entry 1 (the contrast).
- **Read-back.** Other 4-byte-aligned addresses in the test image read back exactly. Each is written and the
  framework value restored with no trap in between.
- **Mutants:** an interrupt vectored in Direct mode, Direct lost after Vectored, BASE[0] read-only 0, and BASE
  aligned to 64 bytes.

## Rules not tested here

- All rules are tested.

## Subtleties

- **Valid addresses.** Only addresses in the test image are known to be valid
  ([#3424](https://github.com/riscv/riscv-isa-manual/issues/3424)), so BASE is not tested with other addresses.
- **Framework state.** `stvec` holds the framework's handler. The test saves it in x9, uses only trampoline entries
  0-23 (which have stubs), and restores it at the end.
