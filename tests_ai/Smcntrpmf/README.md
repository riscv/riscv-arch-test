# Smcntrpmf: cycle and instret privilege-mode filtering

## How it is tested

Generator: `gen/gen_Smcntrpmf.py` (helpers in `gen/cntrlib.py`). mcyclecfg/minstretcfg are M-mode CSRs that
T-SBI does not offer, so every test boots to M-mode and requires Sm, Zicntr and Smcntrpmf. Lower modes are
entered with MRET (MPV=1 for VS/VU) and left through the T-SBI GOTO. Nothing is delegated in an M-boot test, so
every trap from a lower mode goes to M-mode.

Counting is measured with mcycle/minstret: zeroed in M-mode, a block of instructions runs in the mode under
test, the counters are read back in M-mode. M-mode is inhibited in every lower-mode check, so the entry (an MRET
from an inhibited mode), the T-SBI ecall (an exception, not retired) and the handler do not count. Exact counts
are used only where the spec fixes them: 0 with every mode inhibited, and instret over retired instructions
(bounds [n, n+3], exact differences between two block lengths). cycle is only checked as moved / not moved.
Format checks: bit 63 read-only 0, bits 57:0 WPRI (read-only 0, norm:Zicsr_wpri_roz), bits 61:58 read-only 0
for unimplemented modes (run on M-only and M/U harts too).

## Rules not tested here

- `csr_supervisor_access` (MINH read-only 0 through sireg2/sireg5) needs Smcdeleg: it is generated by
  `gen/gen_Smcdeleg.py` as `Smcdeleg/csr_supervisor_access.S`.
- `mcountinhibit_*` (Sm suite), counting by mhpmevent xINH (Sscofpmf suite).
- `cycle_counting`: the cycle a mode change is counted in and the cycles per instruction are free, so only
  nonzero versus zero is checked.

## Subtleties

- `instret_xret`: "should increment instret only if the originating privilege mode is not inhibited" is a
  recommendation, and the NOTE calls the target mode an arguable retirement mode, so each case accepts the count
  by the originating mode or by the target mode (an xRET from an inhibited mode into a counting mode may read 0
  or 1, and the reverse too); with both modes counting an MRET must count exactly once ("The latter do retire").
  `instret_exception` measures the count of one MRET into the mode first, because the handler's MRET back into
  the trapping mode follows the same choice.
- `instret_exception`: <https://github.com/riscv/riscv-isa-manual/issues/1730> (gfavor): a faulting instruction,
  ECALL and EBREAK included, does not retire. The test uses a 32-bit illegal instruction (`csrr mhartid` below
  M-mode); `.word 0` is a 16-bit encoding that the handler skips by 2 bytes.
- A CSR write of minstret replaces that instruction's own increment (norm:mcycle_minstret_wr), and a CSR read
  returns the value before its own retirement; `instret_xret` relies on both.
- mcounteren does not exist on M-only harts; the instret reads below M are guarded by U_SUPPORTED.
- QEMU: VS/VU are never entered from M-mode (mstatus.MPV read-only zero,
  [qemu#4588](https://gitlab.com/qemu-project/qemu/-/work_items/4588), [qemu#4620](https://gitlab.com/qemu-project/qemu/-/work_items/4620)), so the VS/VU cases of the counting tests
  fail there. mcyclecfg OF writable is [qemu#4441](https://gitlab.com/qemu-project/qemu/-/work_items/4441); RV32 minstretcfg
  write clears minstretcfgh is [qemu#4617](https://gitlab.com/qemu-project/qemu/-/work_items/4617).
