# Zvfbfwma: rule-derived tests

One test per `norm:` rule of `src/unpriv/zvfbfwma.adoc`. Generated by `tests_ai/gen/gen_Vzv.py`.

## How the extension is tested

- **Encodings** (`vfwmaccbf16_encoding_vv`, `_vf`): `.word` encodings from the diagrams, vm=1 and vm=0.
- `vfwmaccbf16_op`: one element per case so fflags is checked: an exact case; the sum rounded by frm; the product
  is not rounded (`(-2^-100 * 2^-100) + 1` under RTZ gives 0x3f7fffff, `(2^-100 * 2^-100) + 1` under RNE gives 1.0
  with NX only); overflow by mode; invalid operations (infinity * 0, infinity - infinity) and NaN inputs (canonical
  NaN, NV only for signaling NaNs); signed zeros; an exact subnormal result and an underflowing one.
- `vfwmaccbf16-vv`: operand roles (accumulator in vd, factors in vs1/vs2) with values that change if a role is
  wrong, and vs1 = vs2.
- `vfwmaccbf16-vf`: the scalar from f1, properly NaN-boxed (used for every element) and not boxed (the canonical
  NaN is used: every result is 0x7fc00000 with no flags).
- `Zvfbfwma_depends`: vfwcvtbf16 (Zvfbfmin) and fcvt.s.bf16/fcvt.bf16.s (Zfbfmin).

## Rules not tested here

- `vfwmaccbf16_sew_rsv`: SEW other than 16 is reserved.

## Subtleties

- The operation is defined as widening both factors and an FP32 FMACC, so the BF16 x BF16 product is exact and
  only the sum is rounded; the RTZ and RNE cases above distinguish this from rounding the product first.
- A scalar BF16 operand that is not NaN-boxed reads as the canonical NaN. QEMU 11.1 uses the binary16 canonical
  NaN 0x7e00 instead (read as BF16 it is 2^125), so `vfwmaccbf16-vf` fails there ([qemu#4828](https://gitlab.com/qemu-project/qemu/-/work_items/4828)).
