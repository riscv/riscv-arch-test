# Sdtrig: rule-derived tests for debug triggers

One test per `norm:` rule of the Sdtrig extension that is observable without Debug Mode. The rules are tagged in
`Sdtrig.adoc` and `xml/hwbp_registers.xml` of the RISC-V Debug spec. The tags exist only on
[riscv-debug-spec#1220](https://github.com/riscv/riscv-debug-spec/pull/1220) (head afd3901); upstream main has none
yet. `tests_ai/gen/norm_rules.py --manual <checkout> --rev WORKTREE Sdtrig.adoc xml/hwbp_registers.xml` parses both
files, and its 307 entries are exactly the tags of `normative_rule_defs/sdtrig.yaml`.

Generated by `tests_ai/gen/gen_Sdtrig.py`, with helpers in `tests_ai/gen/sdtriglib.py`.

## How the extension is tested

- **Modes.** Most tests boot to S-mode and program the M-level trigger CSRs (tselect, tdata1, tdata2) through T-SBI.
  Breakpoints (action = 0) are raised in U, S, VS and VU (VS/VU under `H_SUPPORTED`). They land in the S/HS handler
  (medeleg[3] = 1, hedeleg = 0), or in M on harts that hard-wire medeleg[3] to 0. Rules about M-mode triggers, tcontrol,
  optional trigger CSRs that may trap (tinfo, tdata3, mcontext), medeleg, or etrigger/itrigger are `<rule>_Sm.S` files
  that boot to M and require `Sm`.
- **Probing, no parameters.** Every feature is found at run time: the number of triggers, types, match values, sizes,
  chain, select, hit bits, count width, NAPOT maskmax6, and textra/context support. A test looks among triggers 0-3
  for one (or two consecutive) that keep the configuration after a WARL write and read-back (`sdtriglib.probe`).
  Where the result depends on tdata2 (NAPOT, masks), it also reads tdata2 back. Without the feature, the test passes
  vacuously. Probing uses no table entries, so a run-time branch skips the right number.
- **Timing.** mcontrol6 has no timing bit, so a trigger may fire before the matching instruction, just after it, or
  later. Each breakpoint window therefore runs the matching instruction followed by nops, permits one trap, and
  resumes at the end of the window (`rvtest_trap_resume`). xepc must fall inside the window. Exact timing is checked
  where the spec fixes it:
  - for `Sdtrig_action0`, xepc is the matching instruction exactly when that instruction did not execute;
  - for the hit field, 1 means xepc is the matching instruction, 3 the next instruction, and 2 a later one;
  - for icount, the breakpoint comes before the (n+1)th counted instruction;
  - for etrigger/itrigger, mepc is the S handler's entry.
- **xtval.** For mcontrol6, xtval is 0 or an address that was accessed and satisfies the match. For a multi-byte access
  with a range match, any of its bytes is accepted
  ([riscv-debug-spec#1132](https://github.com/riscv/riscv-debug-spec/issues/1132)), and ranges are set up so that
  tdata2 differs from the accessed address. For icount, etrigger and itrigger, xtval is 0.
- **Reentrancy.** S-mode windows run with sstatus.SIE = 1 and sie = 0, and M-mode code runs with mstatus.MIE = 1 and
  mie = 0. MTE is set when tcontrol exists. This arms triggers under both reentrancy options (interrupt enables, or
  tcontrol with medeleg[3] = 0), so either option must fire. Range matches (>=, <, NAPOT, masks, not-equal) are enabled
  only in U/VU, where the window's own loads are the only explicit accesses.
- **etrigger/itrigger.** Delegating the trap to S while keeping breakpoints in M (medeleg[3] = 0) is the
  configuration where every hart must fire: the breakpoint is taken from S before the S handler's first instruction.
  The test defines `SDTRIG_XEPC_IN_VECTOR` so that the M handler returns to the S vector, and the S handler then logs
  the original trap. Both traps are checked in the log.
- **icount.** Counts are exact. A U window is entered with `sret` from S (not counted) and left with T-SBI (`li` +
  `ecall`: one retired instruction and one trap). This makes the decrement, the pending bit, and the breakpoint
  position deterministic. For S-mode, the trigger is armed by the T-SBI call itself, so the first S instruction after
  the return is the first one counted.
- **Mutation check.** `MUTANTS` in `gen_Sdtrig.py` (81 mutants) each flip one expectation to model a design bug, and
  every one fails a test on Sail. The tcontrol mutants were checked on a Sail configuration with
  `breakpoint_reentrancy = Use_tcontrol`, because the ACT Sail configuration has no tcontrol.
- **Vacuous where nothing implements the feature.** `Sdtrig_mscontext_Sm` passes vacuously on every tested simulator,
  since none implements mscontext. The tcontrol tests pass vacuously on ACT Sail, and the textra/context
  tests wherever tdata3 or the context CSRs are absent.
- **Ratified version only.** `Sdtrig_mcontrol6_hit0_1`-`_3` assume tinfo.version 1. A pre-ratification hart that
  sets hit0 = 1 for every firing could fail them.

## Rules not tested, or only partly

- **Need Debug Mode, Sdext or a debugger:** `Sdtrig_no_debug_fires`, `Sdtrig_debug_breakpoint`,
  `Sdtrig_simul_debug_breakpoint_fallback`, `Sdtrig_hit_set_on_action0` (an action=1 trigger),
  `Sdtrig_tdata1_dmode_1`, `Sdtrig_mcontrol6_chain_next`/`_chain_ignore` (dmode = 1 is writable only from Debug Mode),
  and `Sdtrig_tinfo_optional` (it describes what a debugger does). `Sdtrig_action1` is tested only for its WARL part:
  dmode = 0 with action = 1 is never kept.
- **Trace or external signals:** `Sdtrig_action2`-`_action5_rsv`, `Sdtrig_action8_9`, `Sdtrig_action_rsv`,
  `Sdtrig_actions` and `Sdtrig_independent_trigs` (their effects are not visible to the hart), and every
  `Sdtrig_tmexttrigger*` rule (software cannot drive a TM external trigger input).
- **No NMI source:** `Sdtrig_itrigger_nmi`, `Sdtrig_itrigger_enable_nmi`.
- **Handled in M:** `Sdtrig_etrigger_m` and `Sdtrig_itrigger_m`. Both reentrancy options stop etrigger/itrigger on
  traps handled in M-mode, and a hart with neither would re-enter its handler.
- **Not observable with the framework:** `Sdtrig_tcontrol_mte` (a trap into M clears MTE). The framework's M handler
  always ends with `mret`, which restores MTE from MPTE, so the cleared MTE is never seen. `Sdtrig_tcontrol_mpte` and
  `Sdtrig_tcontrol_mte_mret` together cover the rest of the save/restore.
  `Sdtrig_mcontrol6_hit0_unimplemented` is also untestable: software writes of 1 to an implemented hit bit may be
  legalized to 0 (Sail does this), so the implemented bits cannot be identified.
- **UNSPECIFIED or "should":** `Sdtrig_Aext_sc_fail`, `Sdtrig_AMO_store_match`, `Sdtrig_load_zero_rd`, `Sdtrig_tval`
  (which of several equal-priority triggers sets xtval; in these tests all candidates give the same value),
  `Sdtrig_tdata1_multiple_types`, `Sdtrig_csr_tdata2_invalid`, `Sdtrig_textra32_svalue_no_s`/`_sselect_no_s`,
  `Sdtrig_mcontrol6_uncertain*`, and `Sdtrig_mcontrol6_uncertainen_*`. A trigger may always report that it matched
  perfectly, so nothing about uncertain matching is observable.
- **Need XLEN < DXLEN (UXL/SXL = 32 on RV64):** `Sdtrig_xlen_handling`, `Sdtrig_fields`, `Sdtrig_fields_high`,
  `Sdtrig_xlen_modification`, `Sdtrig_tdata2_sign_extend`, `Sdtrig_tdata3_sign_extend`, `Sdtrig_textra32_dxlen64`,
  `Sdtrig_textra64_retain`, `Sdtrig_textra64_xlen32`, `Sdtrig_etrigger_xlen32`, `Sdtrig_itrigger_xlen32`,
  `Sdtrig_mcontrol6_comparisons` (only its "XLEN in the current mode" part; the select=1 part is tested). The address
  representation rules `Sdtrig_pmem`, `Sdtrig_vmem` and `Sdtrig_csr_tdata2_sz2` need translation modes; tdata2 holding
  the test's own addresses exactly is tested in `Sdtrig_tdata2_addr_sz1`.
- **Exercised by every test, no separate file:** the register-access definitions (`Sdtrig_tselect`,
  `Sdtrig_tdata1`/`2`/`3`, `Sdtrig_tinfo`, `Sdtrig_mcontrol6`, `Sdtrig_icount`, `Sdtrig_itrigger`, `Sdtrig_etrigger`,
  `Sdtrig_textra32`/`64` and their `_access` rules), `Sdtrig_tdata_warl`, `Sdtrig_mcontrol6_select_address`,
  `Sdtrig_mcontrol6_size_any`, `Sdtrig_mcontrol6_breakpoint` (xtval is checked on every mcontrol6 breakpoint),
  `Sdtrig_breakpoint_delegated` (main tests; `_Sm` sweeps medeleg[3]), `Sdtrig_scontext_data` and
  `Sdtrig_mcontext_hcontext_data` (the textra context tests), `Sdtrig_trigger_modes_1` and `Sdtrig_mcontext_access`
  (tcontrol and mcontext are in `Sdtrig_trigger_modes`), `Sdtrig_mcontext_implementation` (in
  `Sdtrig_hcontext_implemented`), `Sdtrig_icount_match_non_reexecuted` (the same scenario as `Sdtrig_icount_case`),
  and `Sdtrig_non_precise_priority` (`Sdtrig_priority` measures precision first).
- **Reset values:** `Sdtrig_*_reset`. The DUT's boot code runs before the test and may write trigger CSRs.
- **Not generated:**
  - The deprecated mcontrol (type 2) rules, `Sdtrig_mcontrol*`. Sail 0.16 implements only mcontrol6, so its mutants
    could not be checked.
  - The A-extension and cache-operation rules (`Sdtrig_Aext_lr_op`, `_sc_op`, `Sdtrig_AMO_*`, `Sdtrig_cache_*`,
    `Sdtrig_caches_stores_*`, `Sdtrig_cbo_zero`, `Sdtrig_prefetch`) and `Sdtrig_mult_mem_access`/
    `Sdtrig_multistate_change`/`Sdtrig_mcontrol6_hit0_multiple_accesses` (vector and cm.push). The human ACT tests
    already cover these (`cp_lrsc_*`, `cp_amo`, `cp_cache_*`, `cp_vector_*` in testplans/priv/Sdtrig*.yaml).
  - Textra selections other than mcontext/scontext: `Sdtrig_textra32_mhselect_ignore`/`_mctx_sel`/`_vmid_sel`/
    `_rsv`/`_no_h`, `Sdtrig_textra32_sselect_ignore`/`_asid1`-`3`, and `Sdtrig_textra*_byte_granular`/
    `_byte_mask_applies`.
  - `Sdtrig_icount_textra`, `Sdtrig_etrigger_textra`, `Sdtrig_itrigger_textra`, `Sdtrig_etrigger_hit`,
    `Sdtrig_itrigger_hit`, `Sdtrig_etrigger_vs`/`_vu` and `Sdtrig_itrigger_vs`/`_vu` (the framework's
    `SDTRIG_XEPC_IN_VECTOR` recognizes only the S vector, not the VS vector).
  - `Sdtrig_chain_priority`, `Sdtrig_mcontrol6_match_rsv`, `Sdtrig_tdata1_type_disabled`, `Sdtrig_tdata3_disabled`,
    the `Sdtrig_tinfo_version*` values (only "version >= 1 with mcontrol6" is tested), `Sdtrig_mscontext_access`
    (mscontext is 0x7aa, an M-level CSR number, yet the rule allows S/HS access), and
    `Sdtrig_unimp_csr_illegal`/`Sdtrig_unimplemented_register` (which optional trigger CSRs exist cannot be
    discovered except by accessing them).
  - `Sdtrig_mcontrol6_size_48bit`/`_128bit`: no such instructions or accesses in the tested ISA.

## Subtleties

- **Negated matches on multi-byte accesses.** match = 8/9/12/13 "matches when match = 0/1/4/5 would not match". With
  `address_select_matches_all_addresses = true`, Sail ORs the negated comparison over every byte of the access. So a
  `lw` from A with tdata2 = A fires under match = 8 (A+1 differs from A). `Sdtrig_mcontrol6_match_not_equal` fails on
  Sail for this reason; Spike (CI pin) and Whisper pass it. Not yet reported upstream.
- **Sized data compares.** With select = 1 and size = N, only tdata2[N-1:0] is compared. Sail compares all of tdata2
  ([sail-riscv#2038](https://github.com/riscv/sail-riscv/issues/2038), fix in
  [sail-riscv#2040](https://github.com/riscv/sail-riscv/pull/2040)), so `Sdtrig_mcontrol6_comparisons` fails on Sail.
- **Execute + load chains.** `Sdtrig_mcontrol6_chain` requires a chain to fire _only if_ every trigger matched the
  same instruction. `_chain_start` says "if and only if all the triggers in the chain match at the same time". Spike
  evaluates fetch and load triggers in separate calls, so an execute trigger chained to a load trigger never fires
  there. Whether one instruction's execute and load matches happen "at the same time" is not settled, so both
  outcomes are accepted. The load + load chains must fire.
- **Hit bits.** Sail sets hit0 when a trigger fires but legalizes a software write of 1 to 0. Whether a hit field is
  implemented is therefore inferred from a trigger firing alone (`Sdtrig_multiple_fires`, `Sdtrig_mcontrol6_hit0`).
- **Whisper tcontrol.** The ACT Whisper configuration implements tcontrol (MTE/MPTE writable) but sets
  `trigger_use_tcontrol: false`, so MTE = 0 does not stop M-mode triggers and `Sdtrig_tcontrol_mte_disabled_Sm`
  fails. With `trigger_use_tcontrol: true` it passes. The configuration is already noted in `config/whisper/ci.yaml`
  (the SdtrigSm_tcontrol exclusion).
- **Framework medeleg[2].** A T-SBI GOTO to M-mode restores medeleg[2] from the framework's own saved copy, so the
  etrigger tests rewrite medeleg before every window.
- **Sail with tcontrol.** `breakpoint_reentrancy = Use_tcontrol` also requires medeleg bit 3 to be non-delegatable in
  sail.json.
- **icount.count hard-wired to 1 (Imperas).**
  - Writing an S-enabled icount trigger through T-SBI arms it in the middle of S-mode code. With count = 1 it fires
    at once, inside the probe.
  - So S-enabled icount configurations are probed only after a u-only probe shows that count is writable, and
    `Sdtrig_icount_s` arms s=1 inside its window.
  - Tests that need count > 1 pass vacuously on such harts.
- **Imperas RV32 NAPOT.** The RV32 Imperas configurations do not set `mcontrol_maskmax` (RV64 sets 63). An all-ones
  tdata2 with match=1 reads back 0, which by the spec's discovery procedure means maskmax6 = 32 = XLEN. That cannot
  be: the 2^32 range would need M = 0, which `Sdtrig_mcontrol6_match_napot_legal` forbids.
  `Sdtrig_mcontrol6_match_napot_mask` fails on imperas-rv32gck/gcv for this reason.
- **Writing 0 to tdata1.** A trigger whose type is not writable may keep its type with every enable bit clear, which
  is also disabled, so `Sdtrig_tdata1_write0` accepts that as well as type 0 or 15.
- **tinfo.** `Sdtrig_tinfo_support` checks only "a type sticks ⇒ its tinfo bit is set". A supported type may
  legalize the test's minimal configuration to a disabled trigger (norm:Sdtrig_tdata_warl).
- **etrigger/itrigger codes.** A hart may support only some exception or interrupt codes in tdata2, so tdata2 is read
  back after every write and the expected outcome follows the bits it kept.
- **QEMU** Sdtrig is known to be broken ([qemu#4665](https://gitlab.com/qemu-project/qemu/-/work_items/4665)) and is
  excluded in `config/qemu/ci.yaml`. Its results are recorded but not traced.
