# Ssintro: rule-derived tests for the privileged spec's introduction and CSR chapters

Tests for the `norm:` rules in `src/priv/intro.adoc` and `src/priv/csrs.adoc` that no other tests_ai suite uses.
Ssintro is a directory name, not an extension. Tests require `Sm` (boot to M-mode) or `S` (boot to S-mode); a rule
with both parts has `<rule>.S` (S-boot) and `<rule>_Sm.S`. Generated by `tests_ai/gen/gen_Sx.py`. Mutants are named
`Sx:<mutant>`.

## How the rules are tested

- **Privilege and encodings.**
  - `non_priv_exc`: privileged instructions and CSRs of higher levels raise exceptions from U, S, VS and VU,
    illegal or virtual as hypervisor.adoc defines.
  - `priv_levels_tbl`: mstatus.MPP records 11/01/00 for traps from M/S/U, and never holds 10.
  - `priv_combs_tbl`: M is always present, MPP's legal values match misa.S/U, and S implies U.
- **CSR access** (`Zicsr_rw`, `Zicsr_access`, `Zicsr_illegal_mode`, `Zicsr_illegal_acc`, `Zicsr_higher_priv`). One
  CSR per level is accessed from every mode with all twelve CSR instruction forms.
  - Read-only CSRs (csr[11:10]=11) reject every write form, including csrrs with a zero register and csrrwi with
    uimm=0, and accept reads.
  - Higher modes reach lower-level CSRs.
  - Counter reads below M-mode depend on mcounteren/scounteren bits, which may be read-only 0, so the bits are read
    back first and a read with a 0 bit must raise illegal-instruction.
  - From VS/VU, a write of a read-only CSR raises illegal-instruction (HS-mode could not write it either), and
    hypervisor and VS CSRs by their own addresses raise virtual-instruction.
- **Debug ranges.** M-mode accesses to 0x7b0-0x7bf trap (`Zicsr_debug_illegal`). The Sdtrig CSRs at 0x7a0-0x7af are
  accessible from M (`Zicsr_debug_range`, requires Sdtrig).
- **Fields.**
  - `Zicsr_no_read_side_effects`: every read form, twice, changes nothing.
  - `Zicsr_write_ro`: read-only bits (SD, sip.STIP/SEIP, mip.MSIP/MTIP/MEIP) ignore writes.
  - `Zicsr_wpri_roz`: mstatus, mstatush and menvcfg WPRI bits read 0. The bit lists come from the current register
    figures. mseccfg's WPRI bits are not covered. mstatush and menvcfg exist from Sm 1.12, so they are checked only
    with `SM1P12P0_OR_LATER_SUPPORTED` (cv32e40p is Sm 1.11).
  - `Zicsr_warl`: writes of unsupported values to WARL CSRs never trap.
- **RV32 64-bit CSRs.**
  - `Zicsr_wide_csr_access`: a low-half write leaves the high half alone (menvcfgh and mstatush only on Sm 1.12 and
    later).
  - `Zicsr_high_half_alias`: mcycleh/minstreth see the carry out of the low half, so they alias bits 63:32. The RV64
    builds check nothing.
- **Mutants.** Each rule has at least one mutant (see `MUTANTS` in gen_Sx.py), and every one fails a test on Sail.

## Rules not tested here

- **Definitions with nothing to observe:**
  - `always_priv_level`, `priv_levels_txt` (the table is `priv_levels_tbl`), `priv_combs_txt` (the table is
    `priv_combs_tbl`);
  - `Zicsr_warl_def`, `Zicsr_wlrl` (a software obligation).
- **Vacuous on any testable hart.** `m_mode_mandatory` and `m_level_high_priv_only_mandatory`: every test that
  runs needs M-mode, and that M has the highest privilege is covered by `Zicsr_higher_priv`.
- **Permissions or "should":** `Zicsr_wlrl_exception` (may trap), `Zicsr_wlrl_deterministic` and
  `Zicsr_warl_deterministic` ("should").
- **UNSPECIFIED values:** `Zicsr_field_modulation` and `Zicsr_field_modulation_no_side_effects`. The new value is
  any legal one, and "no side effect" would need a CSR whose write side effect is visible and whose legal values
  another CSR changes.
- **Needs an XLEN change:** `Zicsr_width_modulation` and `Zicsr_width_modulation_no_side_effects`. No configuration
  supports UXL or SXL other than XLEN (see the S suite's UXL notes).
- **Every test relies on it:** `Zicsr_implicit_read`. Implicit reads (stvec on a trap, satp on a walk) behave as
  explicit reads.
- **Other suites:** `Zicsr_nonexistent_rsv` and `Zicsr_high_half_rv64_rsv` are in Ssstrict. Without Ssstrict the
  outcome is free.

## Subtleties

- **WPRI.** WPRI bits must read zero ([#2318](https://github.com/riscv/riscv-isa-manual/issues/2318)). The tests
  use the current figures. A future extension that furnishes one of these bits must update the masks.
- **What counts as a write.** csrrs/csrrc with rs1 != x0 attempt a write even when the register holds 0. csrrwi
  with uimm=0 is a write. Both must trap on read-only CSRs (Zicsr unprivileged chapter).
- **Free-running bits.** mip is not used in the read-side-effect test, because its timer bit follows mtime on its
  own.
- **Known DUT bug.** On QEMU 11.1.3 RV32, mcycleh reads wrong after writes and misses the carry
  ([qemu#4724](https://gitlab.com/qemu-project/qemu/-/issues/4724), fixed on master). `Zicsr_wide_csr_access` and
  `Zicsr_high_half_alias` fail on qemu-rv32-max and qemu-rv32-m.
