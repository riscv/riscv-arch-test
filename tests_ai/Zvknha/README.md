# Zvknha (SHA-256): rule-derived tests

One test per `norm:` rule of `src/unpriv/zvk.adoc` for Zvknha, plus the cross-cutting vector crypto rules
(`veccrypto_*`) applied to Zvknha's instructions. Generated by `tests_ai/gen/gen_Vzv.py` (reference functions in
`gen/vzvlib.py`).

## How the extension is tested

- **Data path.** Element groups are `.word` arrays loaded with `vle<SEW>.v` into vd = v8, vs2 = v16 and vs1 = v24
  (LMUL=8; cases that need more elements than VLEN=32 holds at LMUL=8, such as two 256-bit SM3 or SHA-512 groups
  or three groups, run only when vlenb shows a large enough VLEN); `.vs` forms take the scalar element group from v16 followed by a
  decoy group, which must not be used. Results are stored with `vse<SEW>.v` and checked word by word.
- **Known answers.** SHA-256('abc') (FIPS 180-4): the first two compression steps (vsha2cl then vsha2ch) from H0, and W[16..19] for vsha2ms. The generator's reference functions follow the operation pseudocode in
  `zvk.adoc` and reproduce those standard vectors when chained (checked offline), so expected values do not come
  from a model.
- **Element-group control** (in every element-group directory):
  - `<ext>_vl` and `veccrypto_vl_vstart_egsconstr`: vl = EGS processes group 0 only (group 1, in the tail, stays
    undisturbed with tu), vl = 0 writes nothing, vl = 2*EGS processes both.
  - `<ext>_vstart`: vstart = EGS with vl = 2*EGS for each instruction. The instruction may raise illegal-instruction
    for a nonzero vstart (`vstart_vtype_dep`); if it runs, group 0 (prestart) is undisturbed, group 1 is processed
    and vstart reads 0; if it traps, vstart and vd are unchanged and xtval is 0 or the instruction bits.
  - `veccrypto_lmul_egwconstr`: vl = 0 at every LMUL from mf8 to m8; illegal-instruction exactly when vtype is vill
    or LMUL*VLEN < EGW, computed from vlenb at run time.
  - `veccrypto_eeweqsew` and the `*_egw*` rule: two groups of EGS SEW-wide elements per instruction at vl = 2*EGS,
    a third group left undisturbed.
- **Mutation check.** `gen_Vzv.py`'s `MUTANTS` (`Vzv:<mutant>`) model wrong round functions, wrong immediate
  handling and wrong vl/vstart/EGW/.vs control; each fails a test on Sail (the EGW mutant on a VLEN=128 Sail
  configuration, where mf2 is legal but LMUL*VLEN < EGW).
- `vsha2chl-vv_op`: vsha2cl uses vs1 elements 0-1 and vsha2ch elements 2-3; each state word set alone shows its
  role. `vsha2ms-vv_op`: each input element alone shows its role in W[16..19].
- `Zvknha_sha256`: SHA-256 at SEW=32.

## Rules not tested here

- Reserved encodings and configurations (no mandated outcome): `vsha2chl-vv_Zvknha_sewn32_rsv`, `vsha2ms-vv_Zvknha_sewn32_rsv`, `vsha2chl-vv_vdoverlapvs1vs2_rsv`, `vsha2ms-vv_vdoverlapvs1vs2_rsv`, `veccrypto_vl_vstart_rsv` (vl or vstart not a
  multiple of EGS) and `veccrypto_sew_rsv`.
- Timing: `Zvknha_Zvknhb_dataindeptiming` (data-independent latency is not observable by a functional test).
- `veccrypto_vsins_vdvs2overlap` (vd overlapping the scalar group) is reserved; `veccrypto_indepZkt` states that
  the instructions do not need Zkt, which has no observable consequence.

## Subtleties

- VLEN, ELEN and LMUL support are read at run time: EGW cases with fractional LMUL are illegal at VLEN=128 but legal
  at VLEN=1024 (mf2 with SEW=32), and vill LMULs must trap too.
- The `Zvknha_Zvknhb_*` rules apply to both extensions: SEW=32 here, SEW=64 in `tests_ai/Zvknhb`.
- Sail 0.16 does not raise illegal-instruction for vsha2ch/vsha2cl/vsha2ms when LMUL*VLEN < EGW
  (`zvknhab_check_encdec` passes SEW as the EGW; [sail-riscv#2088](https://github.com/riscv/sail-riscv/issues/2088)), so `veccrypto_lmul_egwconstr` fails on
  VLEN=128 Sail configurations such as `sail-RVB23S64-optional`. The VLEN=1024 max configurations never reach the
  case.
