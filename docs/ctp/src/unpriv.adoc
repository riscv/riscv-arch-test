== Unprivileged Test Plan

Unprivileged tests exercise every instruction using every applicable source and destination register, and reasonable architectural edge values of sources.  They are intended for certification, not verification. For example, they do not stress interrupts arriving in the midst of multicycle instructions.

The unprivileged test plan is written to be easily reviewed by a human, and to be automatically converted to machine-readable coverpoints and tests.
It is defined with spreadsheets in comma-separated value (CSV) format.

=== Unprivileged Tests

Every bin in every coverpoint is associated with a specific test footnote:[cp_asm_count is an exception, just counting the number of times the instruction was executed]. Unprivileged tests sweep some feature under test (such as the destination register rd) while randomizing all applicable register IDs and source values (including values to be loaded from memory).  For example, the unprivileged test for the cp_rd coverpoint of the add instruction contains 32 add instructions, using the 32 different choices of rd.  The rs1 and rs2 register numbers and values are selected randomly. <<Appendix A: Examples>> gives examples of unprivileged coverpoints and tests meeting these requirements and the coverpoints of <<t-I-coverpoints>> for the `add` instruction.  Each test is self-checking, checking the destination register value against one provided by a reference model.  Certain tests also test other state such as stores or floating-point flags, as described in those sections.

[NOTE]
====
The random values are preferably selected in a deterministic way so that regenerating tests use the same random values where possible, minimizing differences between tests.  This can be done by seeding the random number generator with a has of the instruction and coverpoint name.
====

Unprivileged tests are designed to never trap. Their results are independent of the privilege mode in which they are run, so they generally are run only in machine mode.  They generally involve no privileged instructions, except that floating-point and vector tests turn on the mstatus.{FS/VS} bits to enable these extensions.

Notes:

* These coverpoints are adapted from the Imperas https://github.com/riscv-verification/riscvISACOV[riscvISACOV] functional coverage project.

* Register number is a 5-bit ID (e.g. x7), while register value is an `XLEN`-sized number.

* Most coverpoints typically have 32 bins because they exercise all 32 integer registers.

* Cross-products exercise all combinations of two or more coverpoints. They can have a large number of bins.

* Each of these coverpoints can optionally have a modifier appended.  For example, cp_rs1_nx0 is a modified version of cp_rs1, covering all 31 rs1 register numbers excluding x0.  It is used for load/store/jalr instructions that can't rely on address 0 specified by x0 being legal. Modifiers are defined in the extensions that they apply to.

* The cmp_* and cp_*_hazard coverpoints occupy the fuzzy land at the edge of certification and verification.  They are included because they are easy.

* It would be possible to add more floating-point coverpoints such as cmp_fd_fs1_fs2_fs3 but the value is considered low.

* The riscvISACOV test plan had cmp_rd_{rs1/rs2}_eqval coverpoints that compare if rd and one of the sources have the same value.  These are generally hit by the cr_rs1_rs2_edges tests, so they don't add interesting additional coverage and were dropped.  riscvISACOV also had cp_{rs1/rs2/rd}_toggle tests that checked if each bit changed from 1 to 0 and vice versa.  This is trivially exercised by providing all 0s followed by all 1s followed by all 0s again, so they were dropped.

[NOTE]
====
The register edge cases are selected to include extreme values and their immediate neighbors.  They also include walking 1s and an arbitrary intermediate value.  RV64 adds edge cases near the 32-bit boundary to stress W-type instructions.  Immediate edge cases exercise each bit of the immediate, extreme values, and one random intermediate value.
====

==== Hazards

Hazard tests are applied to every unprivileged _Instruction Under Test_ (IUT) that uses a source or destination.
The hazard receives the source from _Secondary_Producer_Instruction_ (SPI) or sends the destination value to a _Secondary Consumer Instruction_ (SCI).  All relevant
Read-After-Write (RAW), Write-After-Read (WAR), and Write-After-Write (WAW) hazards are exercised.  They are tested
with the SI being adjacent to the IUT, and being separated by a small amount.  The SI is selected as a representative
instruction from each of many categories of instructions to exercise forwarding between different functional units.

The categories of SPI and SCI are given in <<t-secondary-producer-instruction-categories>> and <<t-secondary-consumer-instruction-categories>>, respectively.

The types of hazards exercised are given in <<t-hazard-types>>. Not all IUT have a source or destination, so not all hazard types are exercised for every IUT.

[[t-hazard-types]]
.Hazard Types
[options=header]
|===
|Type|IUT First|IUT Second
|RAW|IUT dest -> SCI source|SPI dest -> IUT source
|WAR|IUT source -> SPI dest|SCI source -> IUT dest
|WAW|IUT dest -> SPI dest|SPI dest -> IUT dest
|===

When multiple representative instructions are listed, one is randomly selected from the list for each test. Certain categories and certain instructions in a category (amoswap, fli, fsqrt.d/h/q) only may be selected if the relevant extension is present.  Different source instructions consume one, two, or three sources.  Loads, stores, and atomics always use rs1 as a pointer to a scratch memory location holding a random value. Subword load, store, and atomic IUTs use a random naturally aligned offset in the range [0, 3]. Tests assume mstatus.FS/VS are dirty, if applicable.  Loads and atomics have a memory source operand.  Stores, atomics, and cbo.zero have a memory destination operand.  Vector instructions operate on a vector of 2 32-bit elements.  They are omitted if the vector unit does not support this. Note that li is the pseudo-instruction for addi rd, x0, imm12.

The test cases are as follows:

* If the IUT has {int/pc/fp/vector/memory/CSR} source operand:
** For each IUT source
*** For each hazard_type in {RAW, WAR}
**** For each supported SPI category that can produce the source category (gated by #ifdef EXT_SUPPORTED)
***** For each delay in (0, random[1,3])
****** Pick random unused registers for IUT source(s) and destination from X1-x31 (-x15 for E), f0-f31, v0-v31.  Ok to duplicate source registers.
****** Pick random representative SPI from category, and random unused source registers for SPI.
****** Initialize IUT and SPI sources to random values
****** If hazard_type = RAW // SPI dest -> IUT source
******* SPI dest = random IUT source
******* Perform SPI
******* If delay > 0, perform delay dependent instructions
******* Perform IUT
******* SIGUPD IUT dest or otherwise test IUT result
****** If hazard_type = WAR // IUT source -> SPI dest
******* SPI dest = random IUT source
******* Perform IUT
******* If delay > 0, perform delay dependent instructions
******* Perform SPI
******* SIGUPD IUT dest or otherwise test IUT result
******* SIGUPD SPI dest

* If the IUT has {int/pc/fp/vector/memory/CSR} destination operand:
** For each hazard_type in {RAW, WAR}
*** For each supported SCI category that can read the source category (gated by #ifdef EXT_SUPPORTED)
**** For each delay in (0, random[1,3])
***** Pick random unused registers for IUT source(s) and destination from X1-x15, f0-f31, v0-v31.  Ok to duplicate source registers.
***** Pick random representative SCI from category, and random unused source registers for SCI.
***** Initialize IUT and SCI sources to random values
***** If hazard_type = RAW // IUT dest -> SCI source
****** random SCI source = IUT dest
****** Perform IUT
****** If delay > 0, perform delay dependent instructions
****** Perform SCI
****** SIGUPD SI dest or otherwise test SI result
***** If hazard_type = WAR // SCI source -> IUT dest
****** random SCI source = IUT dest
****** Perform SCI
****** If delay > 0, perform delay dependent instructions
****** Perform IUT
****** SIGUPD IUT dest or otherwise test IUT result
****** SIGUPD SCI dest
** For hazard_type = WAW
**** For each supported SPI category that can produce the source category (gated by #ifdef EXT_SUPPORTED)
***** For each delay in (0, random[1,3])
****** Pick random unused registers for IUT source(s) and destination from X1-x31 (-x15 for E), f0-f31, v0-v31.  Ok to duplicate source registers.
****** Pick random representative SPI from category, and random unused source registers for SPI.
****** Initialize IUT and SPI sources to random values
****** SPI dest = IUT dest
****** Perform SPI // SPI dest -> IUT dest
****** If delay > 0, perform delay dependent instructions
****** Perform IUT
****** SIGUPD IUT dest or otherwise test IUT result
****** Perform IUT // IUT dest -> SPI dest
****** If delay > 0, perform delay dependent instructions
****** Perform SPI
****** SIGUPD SPI dest or otherwise test SPI result

Hazard coverpoints are named cp_hazard_{hazard_type}_{IUT source/dest}_{to/from}_{SI category}_{delay}. IUT source/dest is one of {rs1, rs2, rd, fs1, fs2, fs3, fd, vs1, vs2, vd, memr, memw, csrr, csrw, pc}.

The number of hazard bins for a typical R-type integer IUT is ((2 sources) * (2 hazard types) + (1 destination) * (4 hazard types)) * (8 categories) * (2 delays) = 128 bins.
