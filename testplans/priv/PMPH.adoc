7+| This test plan verifies correct enforcement of PMP in systems implementing the RISC-V Hypervisor extension. It ensures that PMP permissions are applied consistently across all relevant privilege modes (M, HS, VS, and VU), including accesses performed through hypervisor-specific load and store instructions and under one-stage and two-stage address translation. +
The test environment assumes a configurable number of writable PMP entries (PMP_writable_regs), typically 16, and tests are parameterized to allow execution on implementations with fewer writable regions. To reduce runtime, tests are executed with PMP_writable_regs = 16 where supported. The lowest-priority writable PMP region (region PMP_writable_regs−1, typically region 15) is always configured as a background region covering the entire physical address space, using NAPOT addressing with RWX permissions and the L bit set, and with the address register programmed to all ones. Functional coverage is written for PMP_writable_regs−1 regions, while tests are executed assuming PMP_writable_regs regions, ensuring full coverage even when the highest region is reserved as background. +
Unless otherwise specified, tests execute in M-mode while configuring PMP state, and then transition into HS-mode, VS-mode, or VU-mode to observe PMP enforcement. Standard PMP regions are configured using NAPOT addressing with a size of max(g, 8) bytes, placed beyond the program code and not overlapping other standard regions. A default TOR region is aligned to the PMP grain size g and placed beyond the end of the program, with a size of exactly g. PMP grain size is derived from the platform parameter G, where g = 2^(G+2). +
The pmpcfg_i field refers to the 8-bit configuration for region i, located in pmpcfg[i/4] on RV32 or pmpcfg[2*(i/8)] on RV64. Instruction fetch accesses are generated using jal and jalr. Read accesses include {lb, lbu, lh, lhu, lw, lwu, ld}, and write accesses include {sb, sh, sw, sd}. For RV32 systems, instructions lwu, ld, and sd are excluded. Legal PMP permission encodings tested are {000, 001, 011, 100, 101, 110}, with the W=1, R=0 combination treated as reserved and unpredictable. +
For tests involving address translation, valid VS-stage and G-stage page tables are configured as required. Proper privilege mode transitions between HS, VS, and VU are explicitly performed to validate correct enforcement in virtualized contexts. +
After modifying PMP CSRs, synchronization is performed to ensure consistent behavior. Since PMP permissions are not cached in translation structures, PMP changes are expected to take effect immediately; however, when PMP changes are combined with updates to translation structures, appropriate fencing is used. SFENCE.VMA is issued after VS-stage page table updates, and HFENCE.GVMA with rs1 = x0 and rs2 = x0 is issued after G-stage updates. On systems where satp.MODE is read-only zero, SFENCE.VMA may raise an illegal instruction exception; such traps are expected and may be ignored for test purposes. Memory barriers are used where required to ensure proper ordering of configuration changes relative to memory operations.

[NOTE]
====
* Test Configuration Notes
* hypervisor loads and stores depend on PMP
* hlvx does not override PMP execute-only
* PMP intgeraction with fences G and VS-stage
* General Setup for All Tests:
* Use PMP_writable_regs = 16 for test runtime optimization
* Configure bottom region (region 15 or PMP_writable_regs-1) as background: pmpcfg_n.A=NAPOT, RWX permissions, pmpcfg_n.L=1, pmpaddr_n=All_ones
* Execute in M-mode unless specified otherwise
* Standard regions use NAPOT of max(g,8) bytes, placed beyond code without overlapping other standard regions
* Default TOR regions aligned to grain size g, starting beyond program end, size g
* After PMP CSR writes, issue sfence.vma or hfence.gvma for synchronization
* Handle sfence.vma illegal instruction traps on systems with satp.MODE read-only zero
* Legal pmpcfg.XWR combinations: {000, 001, 011, 100, 101, 110} (W=1,R=0 is reserved)
* Grain size g = 2^(G+2) where G is the PMP grain size parameter
* For RV32 systems, exclude lwu, ld, sd instructions from testing
* Address Translation Setup:
* Configure valid G-stage page tables for two-stage translation testing
* Use appropriate VMID and ASID values for TLB management tests
* Set up hgatp register for G-stage translation control
* Configure proper privilege mode transitions between HS, VS, and VU modes
* Synchronization Requirements:
* Issue HFENCE.GVMA with rs1=x0, rs2=x0 after PMP changes affecting translation structures
* Use appropriate memory barriers for cache coherency testing
* Ensure proper ordering of configuration changes relative to memory operations
