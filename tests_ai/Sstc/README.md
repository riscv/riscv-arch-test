# Sstc: rule-derived tests

The Sstc chapter (`src/priv/sstc.adoc`) only declares the CSRs and the STCE bits. The behavior is tagged where `stimecmp`, `menvcfg`, `mip`/`sip` and `mcounteren` are defined (`supervisor.adoc`, `machine.adoc`). This suite tests every rule there that mentions `stimecmp` or STCE. Generated by `tests_ai/gen/gen_Sstc.py`.

How the extension is tested:

- **Machine mode is used only where it must be.** Every test except one boots to S-mode, so the suite runs in RVA23 certification. The exception is `mip_sip_stip_op_Sm.S`, the delegation part of `mip_sip_stip_op`, which must change `mideleg`; it requires `Sm`. M-level state (`menvcfg.STCE`, `mcounteren.TM`, `mip`) and M-mode accesses to `stimecmp` go through T-SBI CSR calls.
- **Expected traps and interrupts** are checked in the framework trap log, through trap windows (`../README.md`). U, VS and VU cases enter the mode with `sret` and return with a T-SBI GOTO. Each illegal- or virtual-instruction case checks the cause, xepc, xtval ∈ {0, instruction bits}, and the mode the trap came from (xPP and SPV). Interrupt cases check that exactly the expected interrupt was taken, and from which mode.
- **Access control** (`menvcfg_stce_*`, `mcounteren_tm_*`):
  - All eight CSR instruction forms (read-only, write-only, swap, set, clear, and the three immediate forms) run in S-mode, plus `stimecmph` on RV32.
  - TM is swept with STCE=0 to show STCE alone denies access, and vice versa.
  - U-mode access must trap even when STCE, TM and scounteren.TM are all 1.
  - With H, VS-mode access with menvcfg.STCE=0 or mcounteren.TM=0 must raise illegal-instruction, not virtual-instruction. A VS-mode write of `stimecmp` must land in `vstimecmp`.
  - Negative dependency: TM=0 does not stop the comparison from driving STIP.
- **The comparison** is swept through stimecmp = 0, = `time`, = `time` + 2^32 and + 2^40, = 2^63, and all ones. The 2^32 offsets keep the low halves equal, so a 32-bit comparison is caught; 2^63 catches a signed comparison. STIP is checked in both `sip` (S-mode) and `mip` (M-mode read). With mtimecmp written through `RVMODEL_MTIMECMP_ADDRESS`, the two timers are checked not to cross.
- **Interrupt delivery** sweeps (sstatus.SIE, sie.STIE) in S-mode and U-mode, with STI pending and not pending. In U-mode SIE is set through SPIE, and the interrupt must be taken regardless of SIE.
- **Transitions.** henvcfg.STCE must read 0 after menvcfg.STCE is cleared while it held 1. A software-set `mip.STIP` must settle to the comparison result when STCE is set.
- **H sections** run only `#if defined(H_SUPPORTED)`. Traps from VS and VU go wherever the framework's delegation sends them (HS, since it clears hedeleg); the checks do not depend on which handler took them.
- **Mutation check.** `gen/mutate.py` has 8 Sstc mutants (signed or 32-bit comparison, U-mode leak, SIE gating STI in U-mode, TM ignored, writable mip.STIP, virtual- instead of illegal-instruction, sticky STIP). Each one fails a test on Sail.

Rules not covered:

- `menvcfg_stce_rdonly0` and `henvcfg_stce_rdonly0` apply only when Sstc is not implemented, while this suite runs only when it is. They belong in a suite gated with `FORBIDDEN_EXTENSIONS: [Sstc]`.
- `mip_stip_no_stimecmp_acc` and `mip_stip_no_stimecmp_mmode_write` describe a hart without stimecmp. Their STCE=0 equivalent, the reverted writable `mip.STIP`, is tested in `menvcfg_stce_zero_op`.
- The VS-level rules are not generated yet: `vstimecmp_exist`, `vstimecmp_sz`, `vstimecmp_acc`, `henvcfg_stce`, `henvcfg_stce_op`, `henvcfg_stce_zero_op`, `hcounteren_acc`, `hip_vstip_op`, `hip_vstip_clear`, `hip_vstip_enable`, `hip_vstip_vstimecmp_op`, `hip_vstip_acc` (its Sstc part), `menvcfg_stce_zero_vstip`. They need `hideleg` control and `htimedelta` sweeps; `TestFile.window()` already supports VS and VU.
- Rules that mention STIP but belong to other suites: `mip_stip_mie_stie_op`, `mip_sxip_mie_sxie_rdonly0` (S/Sm), and `vsip_vsie_sti`, `mip_mie_alias`, `hvip_acc`, `hip_vstip_vstie_acc_op`, `hip_vstip_defined_v0` (H).
- VU-mode access with menvcfg.STCE=0 is not tested. The STCE rule says illegal-instruction, while VU's insufficient privilege for an HS-qualified CSR says virtual-instruction, and no clarification resolves the conflict.
- `time` == `stimecmp` exactly is not tested, because the test cannot stop `time`. The "≤" side is tested with stimecmp = the `time` just read.
- `time` wrapping at 2^64-1 cannot be reached.

Subtleties:

- When STCE changes, STIP takes an UNSPECIFIED value ([#1636](https://github.com/riscv/riscv-isa-manual/issues/1636)). Tests write `mip.STIP` after clearing STCE before checking it.
- `stimecmp` has no reset value ([#1169](https://github.com/riscv/riscv-isa-manual/issues/1169)), so every test writes it first.
- All ones in `stimecmp` is not a "timer off" sentinel ([#2237](https://github.com/riscv/riscv-isa-manual/issues/2237)). It reads as not pending only because `time` < 2^64-1.
- STIP need only reflect a comparison change "eventually". Each check polls `sip` up to 500 times first, in a bounded wait loop that contains no checks. Steady-state negatives poll 50 times for a glitch.
- Reading `time` below M-mode needs mcounteren.TM=1, so the TM=0 test never reads `time`. Tests that read `time` require `Zicntr`.
