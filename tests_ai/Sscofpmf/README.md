# Sscofpmf: rule-derived tests for count overflow and mode-based filtering

There is one test per `norm:` rule about Sscofpmf. The rules come from `src/priv/sscofpmf.adoc`, plus the LCOFI and
`mhpmevent*h` rules in `machine.adoc`, `supervisor.adoc` and `hypervisor.adoc`. The tests are generated by
`tests_ai/gen/gen_Sscofpmf.py`.

## How the extension is tested

- **Modes.** Tests boot to S-mode and reach the M-level CSRs through T-SBI: `mhpmevent*`, `mhpmcounter*`,
  `mcountinhibit`, `mcounteren`, `mip`, `mie` and `scountovf`. They enter U, VS and VU with `sret`. Some parts need
  `mideleg` changes, M-mode trap windows or M-mode execution. These are `<rule>_Sm.S` files that boot to M and
  require `Sm`: MINH filtering, an undelegated LCOFI, the M-mode priority order, M-mode `scountovf` accesses, and
  the RV32 `mhpmevent*h` presence.
- **Counting.** Events are implementation-defined, so counting uses the DUT macros:
  - `RVMODEL_HPM_COUNTER` selects the counter.
  - `RVMODEL_MHPMEVENT_VAL` selects the event.
  - `RVMODEL_MHPMEVENT_CODE` makes that event count in the current mode.

  To count, a test presets the counter with every xINH bit set and enables counting only in the mode under test.
  M-mode stays inhibited, so T-SBI handler code is not counted. The test then runs the event code and sets every
  xINH bit again. It checks only whether the counter moved or wrapped, never by how much, so events that count
  every instruction or cycle also work. Counting checks are compiled only when `RVMODEL_MHPMEVENT_VAL != 0`. On DUTs
  that declare they cannot count (Spike), only the event-independent checks run.

- **Overflow.** The counter's implemented bits are probed: the test writes all ones and reads back R. Presets are
  then built from R:
  - R wraps: OF is set.
  - R >> 1 crosses into the top bit: this is not an overflow.
  - 2^32-1, when more than 32 bits are implemented: the carry is not an overflow.

  OF, `scountovf`, `sip.LCOFIP`, `mip.LCOFIP` and the interrupt are checked after each preset.

- **Event-independent checks.** These use software writes:
  - OF is set and cleared directly (issue 1981).
  - The xINH bits are written and read back.
  - Counters are written across the wrap, which must not overflow.
  - `scountovf` is compared with the OF bits read back from all 29 `mhpmevent`s, under sweeps of `mcounteren`,
    `hcounteren` and `scounteren`.
  - LCOFIP and LCOFIE are written in `mip`/`mie`, `sip`/`sie` and `vsip`/`vsie`.
- **WARL bits are read back.** Counter-enable bits, OF of unimplemented counters, and `hideleg[13]` can be read-only
  zero. Each case uses the value read back, and `TestFile.either` where the cases differ.
- **Interrupts.** The tests take LCOFI:
  - in S-mode and from U-mode, delegated, and in HS-mode from VS-mode when `hideleg[13]=0`;
  - in M-mode from M, S and U, undelegated;
  - in VS-mode, when `hideleg[13]` is writable.

  Priority tests make LCOFI and a higher-priority interrupt pending together. Both entries are read from the trap
  log, and LCOFI must come second. A pairing is skipped when the other interrupt is not implemented (its enable bit
  reads 0), when LCOFI is not routed to the mode under test, or, in M-mode, when the other interrupt's `mideleg`
  bit is read-only one.

- **Mutation check.** `MUTANTS` in the generator lists 32 expectation flips, for example: signed overflow, overflow
  at bit 31, an ignored SINH, VS filtered by SINH, a sticky LCOFIP level, `scountovf` masked by `scounteren`, and
  LCOFI before SSI. Run `tests_ai/run_mutants.sh Sscofpmf: config/sail/sail-rv64-max`, and use `sail-rv32-max` for
  the RV32-only mutants. Every mutant fails a test on Sail.

## Rules not tested here, or only partly

- **Need a hart without Sscofpmf.** These belong in the S/Sm suites with `FORBIDDEN_EXTENSIONS: [Sscofpmf]`:
  - `mip_lcofip_mie_lcofie_rdonly0`;
  - the last sentence of `sip_sie_Sscofpmf`;
  - `std_super_intr_impl` for LCOFI;
  - the "only if" half of `mhpmeventh_presence`.
- **Other suites:**
  - Zihpm, Zicntr and Sm:
    - `mhpmevent_sz_warl_op`, `mhpmevent_enc` (event 0 is "no event");
    - `mhpmcounter_mhpmevent_rdonly0`, `mhpmcounter_sz`;
    - the `mcountinhibit_*` rules;
    - `cycle_instret_hpmcounter_op_rdonly`, `cycleh_instreth_hpmcounternh_op_rdonly`;
    - the counter halves of `mcycleh_minstreth_mhpmh_op`. Only its `mhpmevent*h` half is tested here.
  - Smcdeleg/Ssccfg: `Ssccfg_virtual_scountovf_vs_vu` (CDE=1), `Ssccfg_lcofi_mvip_mvien` and
    `Ssccfg_lcofi_hvip_hvien`. The tests here clear `menvcfg.CDE`.
  - Smctr: the `LCOFIFRZ` rules (`mctrctl_lcofifrz_op`, `mctrctl_impl`, `vsctrctl_lcofifrz_op`,
    `sctrstatus_frozen_set`, `ctr_freeze_vs`).
  - S: `scause_exccode_enc_tbl`. Cause 13 is checked wherever an LCOFI is taken.
- **Priority orders, partly.** In `intr_m_mode_pri`, `sip_sie_priority_bit_order` and `hsint_priority`, only the
  position of LCOFI is tested. It is tested against SSI, STI and SEI (M and S) and against VSEI, VSSI and VSTI (HS).
  MEI, MSI, MTI and SGEI need platform interrupt sources and are left to the Sm and H suites.
- **Vacuous without counting.** Most counting checks are compiled out when `RVMODEL_MHPMEVENT_VAL` is 0:
  `hpmcounter_overflow`, `count_overflow_interrupt`, `mhpmevent_of_bit_set`, `lcofip_op`,
  `mip_lcofip_reflects_overflow`, the counting half of `mhpmevent_inh_op`, and steps 3-5 of `mhpmevent_of_op`.
- **Not constrained by the spec.** Whether a software write of OF=1 sets LCOFIP is not tested. Writes of OF are not
  count overflows (`count_overflow_trigger`), but `lcofip_op` says "when an OF bit is set". Tests wait for, and clear,
  any LCOFIP such a write causes before they rely on LCOFIP. Bits 2:0 of `scountovf` (no OF source) are not
  checked.
- **Hart-dependent.** `vsip_vsie_lcofi` runs its aliasing and VS-delegation half only where `hideleg[13]` is
  writable. On Sail, Whisper and QEMU it is read-only zero (none claims Shlcofideleg), so that half has not run on
  any DUT yet.

## Subtleties

- **Software writes of OF.** <https://github.com/riscv/riscv-isa-manual/issues/1981>: "Software, on the other hand,
  can freely write 0 or 1 to the OF bit."
- **Mode transitions in filtering tests.** A "must not count" case never leaves uninhibited a mode the hart
  passes through. The trap handlers and T-SBI run in M (and S/HS when returning from U, VS or VU), and
  `mhpmevent_inh_op` clears `hedeleg[8]` so that a VU ecall skips VS.
- **LCOFIP is set by the transition, not the OF level.** A handler clears LCOFIP while OF stays 1 ("The LCOFIP bit is
  cleared by software before servicing ..."). `lcofip_op` checks that a cleared LCOFIP stays clear while OF=1.
- **Delegation.** <https://github.com/riscv/riscv-isa-manual/issues/1800>: LCOFI follows the standard
  `mideleg`/`hideleg` delegation. `mideleg[13]` is WARL: "An implementation can choose to subset the delegatable
  traps" (`norm:medeleg_mideleg_warl`), and it may even be read-only one (`norm:mideleg_rd1_lower_level`).
  - The `_Sm` files probe it by writing 1 and 0 and reading back. Each case runs only with a value the bit can
    hold, and expects the routing that value gives: M-mode when it is 0, S-mode when it is 1.
  - S-mode files cannot read `mideleg`. They observe it as D: an M-mode (T-SBI) write of `mie.LCOFIE` shows in
    `sie` iff LCOFI is delegated, since `sip`/`sie` bits of undelegated interrupts are read-only zero.
  - With D=1, LCOFIP is read and cleared in `sip`; with D=0, in `mip` through T-SBI. LCOFIE is always set in `mie`.
    An LCOFI is expected in S/HS-mode when D=1 and in M-mode otherwise.
  - Cases that need delegation are skipped when D=0: the `sip`/`sie` read-write and enable sweeps (which then
    check that `sip`/`sie` bit 13 read zero instead), the `vsip`/`vsie` aliasing, and the S/HS priority orders.
- **AIA and `hideleg[13]`.** <https://github.com/riscv/riscv-isa-manual/issues/1785>: when AIA is implemented, it
  overrides the base rule.
  - A writable `hideleg[13]` is accepted with Ssaia even without Shlcofideleg.
  - `hvien[13]` is cleared, so the AIA alias of `vsip[13]` to `hvip[13]` is not in play.
- **Smcdeleg.** <https://github.com/riscv/riscv-isa-manual/issues/2287>: with `menvcfg.CDE=1`, VS/VU reads of
  `scountovf` trap. The VS tests clear CDE.
- **RV32 `mhpmevent*h`.** <https://github.com/riscv/riscv-isa-manual/issues/1520>: these CSRs exist so that OF/xINH do
  not take RV32 event bits.
- **Bits 57:56 of `mhpmevent`.** <https://github.com/riscv/riscv-isa-manual/issues/1578>: they are reserved and not
  tested here. QEMU keeps them writable
  ([qemu#4722](https://gitlab.com/qemu-project/qemu/-/work_items/4722)).
- **Implemented counter width.** `mhpmcounter`s are WARL with up to 64 bits, and overflow is "unsigned overflow of
  the implemented counter bits". Expected values are therefore derived from the read-back R, not from 2^64.
- **Known DUT bugs these tests show:**
  - Stock QEMU 11.1.2:
    - every LCOFI bit-13 path except `mip.LCOFIP` writes is broken
      ([qemu#3969](https://gitlab.com/qemu-project/qemu/-/work_items/3969)). This is fixed in 11.1.3, the CI pin.
  - QEMU 11.1.3 on RV32:
    - overflows are lost after a two-half preset ([qemu#4723](https://gitlab.com/qemu-project/qemu/-/work_items/4723));
    - `mhpmcounterh` readback is wrong ([qemu#4724](https://gitlab.com/qemu-project/qemu/-/work_items/4724)).
  - QEMU 11.1.3 and master on both XLENs, not yet reported: stopping a counter by setting an xINH bit discards the
    counts it made. Reproducer: `~/repros/2026-11-06-qemu-sscofpmf-xinh-stop-loses-count.tar.gz`. This fails
    `mhpmevent_inh_op`, `mhpmevent_inh_op_Sm` and `hpmcounter_overflow`.
