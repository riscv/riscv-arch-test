
=== I Base Integer Extension

<<t-I-coverpoints>> summarizes the coverpoints for the I extension.  The Type column is used to generate tests with the appropriate operands. An x in the RV32 or RV64 column indicates that the instruction is supported in that XLEN.  The remaining columns refer to coverpoints defined in <<t-unprivileged-coverpoints>>.  An x in a coverpoint column selects that coverpoint.  Any other entry selects a modified coverpoint whose name is the column name followed by an underscore and the entry.  For example, nx0 in the cp_rs1 column selects cp_rs1_nx0.  <<t-I-modified-coverpoints>> defines the modified coverpoints.

<<t-I-normative-rules>> summarizes the normative rules in the RV{32/64}I specification and the unprivileged coverpoints that check they have been exercised.  Privileged coverpoints related to integer instructions are described in the relevant parts of Privileged Test Plan such as <<Sm Machine-Mode CSRs and Instructions, Sm>> and <<ExceptionsSm Machine-Mode Exceptions, ExceptionsSm>>. In particular, `ebreak` and `ecall` are only tested in the Privileged test plan because their behavior is UNSPECIFIED without an `mtvec` trap vector CSR. Reserved behaviors are checked in <<Ssstrict>>. Note that the testplans always test the following fundamental capabilities, even if no normative rule is cited:

* Opcodes (cp_asm_count)
* All Source and Destination Registers (cp_rs1, cp_rs2, cp_rd)
* Edge values (cp_rs1_edges, cp_rs2_edges, cp_imm_edges, cr_rs1_rs2_edges, cr_rs1_imm_edges)
* All other bitfields in the instruction

HINTs are covered as follows:

* Standard HINTs encoded as integer computational instructions with rd = `x0` are executed by the x0 bin of cp_rd.  These instructions are `lui`, `auipc`, `addi`, `andi`, `ori`, `xori`, `add`, `sub`, `and`, `or`, `xor`, `sll`, `srl`, and `sra`, plus `addiw`, `addw`, `subw`, `sllw`, `srlw`, and `sraw` on RV64.
* `fence` HINTs are covered by cp_custom_fence_pred_succ and cp_custom_fence_reserved.
* Ratified HINTs such as Zihintpause and Zihintntl are covered in <<Zi*  Additional Unpriv Extensions>>.
* The semihosting markers `slli x0, x0, 31` and `srai x0, x0, 7` are standard HINTs, but they are not tested.
* Custom HINTs are not tested.  They are the other rd = `x0` encodings of `slti`, `sltiu`, `slli`, `srli`, `srai`, `slt`, and `sltu`, plus `slliw`, `srliw`, and `sraiw` on RV64.  These instructions use cp_rd_nx0 and the cmp_*_nx0 coverpoints, so their tests never write `x0`.
