# M: rule-derived tests

One test per normative rule of the M chapter (`src/unpriv/m-st-ext.adoc`); every rule in the chapter has a test. Generated by `tests_ai/gen/gen_M.py`. Expected values are computed in the generator from the arithmetic in the rules, separately for RV32 and RV64.

How the extension is tested:

- **Edge-class cross products.** Each instruction runs on the cross product of 13 operand classes (0, 1, 2, -1, -2, MIN, MIN+1, MAX, MAX-1, 2^(XLEN/2), 2^(XLEN/2)-1, 0x55.., 0xAA..). The classes are sized to the operation width (XLEN, or 32 for W forms). They catch sign-handling errors, carries across the half-word boundary, and the corner cases of division.
- **Signedness.** The MULH/MULHU/MULHSU crosses include operands with the sign bit set in either position, so treating an operand with the wrong signedness, or swapping MULHSU's signed operand, gives a different result.
- **W forms (RV64 only).** Their files put the whole body under `#if __riscv_xlen == 64`, so they pass trivially on RV32; no MXLEN parameter is used.
  The low halves carry the edge class and the upper halves are random, because they must be ignored. Each W test also checks that results with bit 31 set are sign-extended, including DIVUW/REMUW and divide by zero. For W forms, a divisor whose low half is zero is a divide by zero.
- **Micro-architectural hazards.** Each instruction is tested with rd=rs1, rd=rs2, rs1=rs2, x0 sources, an x0 destination, and a dependent pair that consumes a multi-cycle result immediately. The spec recommends fusible pairs (MULH[[S]U]+MUL, DIV[U]+REM[U]); those are tested along with near misses that must not be fused (rdh equal to a source, swapped sources).
- **Gating.** The multiply tests require `M` or `Zmmul`, because Zmmul has identical MUL semantics. The divide tests require `M`.

Rules not covered here:

- The encoding rules in `rv-32-64g.adoc` (`mul_enc` ... `remuw_enc`) are only exercised implicitly: the assembler emits the encodings, and every test executes them.
- The Zmmul chapter's rules (`Zmmul_insns`, `Zmmul_enc_same`, `M_implies_Zmmul`) belong to a Zmmul suite. Here they only justify gating the multiply tests on `M` or `Zmmul`.
- `misa_extensions_disabling` (machine chapter) has no test for M. Clearing `misa.M` makes the M opcodes _reserved_, not necessarily illegal. A hart with Zmmul also keeps MUL legal, so no outcome is inconsistent with the spec.
- The recommended code sequences and fusion are not normative. They only motivate the fused-pair cases.

Subtleties:

- In MULHSU, rs1 is the signed operand and rs2 the unsigned one ([#270](https://github.com/riscv/riscv-isa-manual/issues/270), [#463](https://github.com/riscv/riscv-isa-manual/issues/463)).
- REMW/REMUW sign-extend the 32-bit result even on divide by zero, and "dividend" there means rs1[31:0] ([#56](https://github.com/riscv/riscv-isa-manual/issues/56)).
- The unsigned DIVU/REMU of the signed-overflow bit patterns (MIN, -1) must not apply the signed-overflow special case. `signed_div_overflow` checks this.
