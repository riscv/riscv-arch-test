# Ssnpm: rule-derived tests for senvcfg.PMM and henvcfg.PMM (U, VS and VU)

Generated by `gen/gen_Spm.py` with the other pointer-masking suites; the shared mechanics are in
`../Smnpm/README.md`. Files boot to S-mode (HS with H); U, VS and VU windows are entered with sret, and traps return
to HS-mode (the framework clears hedeleg).

## How the extension is tested

- `senvcfg_pmm_ssnpm`: U-mode loads, stores, AMOs and LR/SC follow senvcfg.PMM; S-mode does not.
  `senvcfg_pmm_ssnpm_H` (H): VU-mode does and VS-mode does not. `senvcfg_pmm_ssnpm_absent` (FORBIDDEN Ssnpm; boots to M-mode): the field is read-only zero, and a U-mode ld of a tagged VA under Sv39 page-faults (under Bare, masking and a hart that drops high physical address bits would read the same page).
- `senvcfg_pmm_enc`: the WARL encodings and CSR forms.
- `senvcfg_pmm_immediate`: senvcfg.PMM toggled 00/11/00/10/00 with U (and VU) accesses after each write and no
  SFENCE.VMA anywhere.
- `henvcfg_pmm_op` (H): the WARL values, VS-mode accesses follow henvcfg.PMM, and VU, U and HS do not.
  `henvcfg_pmm_op_absent` (FORBIDDEN Ssnpm, also RV32 henvcfgh): read-only zero.
- `ssnpm_definition`: U, VU and VS follow their registers, S does not, with different values set at once.
- `pm_uxl_clear`: UXL=1 (through T-SBI) clears senvcfg.PMM; with UXL read-only, the ignored write leaves PMM alone.
- `pm_ignore_pa` (hgatp Bare, access faults) and `pm_ignore_pa_gstage` (hgatp Sv39x4 and Sv48x4, guest-page faults
  outside the GPA range): guest-physical addresses (vsatp Bare) are zero-extended.
- `pm_ignore_va`: VS (supervisor pages) and VU (user pages) under vsatp Sv39 sign-extend.
- `pm_mxr_exception`: VS and VU with vsstatus.MXR=1 alone, then HS-level sstatus.MXR=1 alone: not masked; both 0:
  masked again.
- `pm_ignore_pa_gstage` with hgatp Sv48x4: the 50-bit GPA overlaps the PMLEN=16 masked bits 49:48 (the pm-two-stage case).

## Rules not tested here

- hstatus.HUPMM and HLV/HSV masking: the H suite (`hstatus_hupmm_*`).
- `senvcfg_pmm_enc`'s RV32 form: RV32 senvcfg has no bits 33:32.
- VSXL=32 clearing henvcfg.PMM: the rule names UXL/SXL only, and no configuration has a writable VSXL; not generated.
- MPRV=1 with MPV=1 (effective VS/VU through MPRV): not generated yet.
- Zicfiss shadow-stack accesses (explicit accesses that are masked, isa-manual#1533) and the other CBOs: not
  generated; ACT's own Ssnpm suite covers SSPUSH/SSPOPCHK (qemu#4758).
- U-mode virtual addresses under satp: `../Supm/pm_ignore_va_Sm.S` (U code needs user pages, the S trap handler
  supervisor ones).

## Subtleties

- For VS/VU, MXR is in effect when sstatus.MXR or vsstatus.MXR is 1
  ([#1915](https://github.com/riscv/riscv-isa-manual/issues/1915)). QEMU misses the HS-level case (it keeps HS's MXR
  in a shadow register while V=1; [qemu#4819](https://gitlab.com/qemu-project/qemu/-/work_items/4819)).
- The hypervisor should HFENCE.GVMA when PMLEN changes with hgatp Sv57x4/Sv48x4 (pm-two-stage); the tests use
  Sv39x4, where XLEN-PMLEN is never below the GPA width, so no fence is needed.
