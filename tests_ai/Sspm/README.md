# Sspm: rule-derived tests for S-mode pointer masking

Sspm only says that S-mode has pointer masking with "some facility" of the execution environment to control it.
These tests boot to S-mode and use T-SBI writes of menvcfg.PMM as that facility. `pm_ignore_upper_bits` requires
that the facility can enable masking (writes of 10 and 11 do not both read 00). Generated by `gen/gen_Spm.py`; the
shared mechanics are in `../Smnpm/README.md`.

## How the extension is tested

- `pm_ignore_upper_bits`, `pm_ignore_pa`, `pmlen_supported_values`: Bare (physical) accesses with tags and every
  PMLEN boundary bit.
- `pm_ignore_va`: Sv39, Sv48 and Sv57 (each when supported), through the identity map and the high-half alias, plus
  an unmapped valid VA whose page fault must report 0 or exactly the transformed VA.
- `pm_apply_explicit` (Bare) and `pm_explicit_accesses` (Sv39): every class of explicit access.
- `pm_not_apply_implicit`: fetches from tagged addresses fault (Bare and Sv39). `pm_cpu_only`: a page-table pointer
  with physical bit 48 set is not masked by the walk (load access fault), with a control pointer that works.
- `pm_misaligned_equivalence`: within-page and page-crossing misaligned accesses, Bare and Sv39 (incl. the alias).
- `pm_csr_hw_apply`: stval of page faults on tagged unmapped VAs (Sv39, Sv48) is the transformed VA (or 0).
- `pm_no_csr_sw`, `pm_warl_unaffected`: sepc/stval software writes of valid addresses (Sv39/Sv48/Sv57 extremes
  when supported, the image address) read back exactly whatever PMM is.
- `pm_mxr_exception`: sstatus.MXR=1 disables masking for loads, stores and AMOs, Bare and Sv39; MXR=0 re-enables.
- `pm_mode_only_dependency`: positive and negative VAs, with bit 63 set or clear in the tag, are masked alike.
- `pmlen_future_reserved`: PMM=01 written to menvcfg (and senvcfg with Ssnpm) reads a legal value that governs.

## Rules not tested here

- See `../Smnpm/README.md` (`pm_debug_trigger`, `pm_no_trap_vector_mask`, definitions and permissions).
- The SFENCE/HFENCE/SINVAL note: those are not memory accesses whose result depends on the address being masked.

## Subtleties

- xtval for invalid addresses may be converted to another invalid address, so only valid transformed VAs get an
  exact check ([#1844](https://github.com/riscv/riscv-isa-manual/issues/1844)).
- The page-table-walk test assumes no memory at physical address 2^48 + (the table's address).
