# Smstateen: rule-derived tests

One test per `norm:` rule of the state-enable chapter (`src/priv/smstateen.adoc`) that involves `mstateen`. The
`srmcfg` rules, including `mstateen0_srmcfg_op`, are in `../Ssqosid`. The supervisor-level rules (what S/HS-mode
sees of `sstateen` and `hstateen`) are in `../Ssstateen`, which never touches `mstateen` and so also runs where
M-mode is the execution environment (RVA23). Both suites are generated by `tests_ai/gen/gen_Smstateen.py` with `gen/smstateenlib.py`.

How the extension is tested:

- **Expectations come from the bits read back.** Every defined stateen bit is WARL and may be read-only zero or one,
  and the state it controls is optional. Each gating test therefore probes the state from S-mode at the boot
  configuration, then after every write to a stateen bit reads the bit back, and computes the legal outcome of each
  access at run time (`smstateenlib.predict`): x6 = mstateen bit AND probe, x8 = hstateen bit, x9 = sstateen bit.
  A writable or read-only-one mstateen bit whose state the probe found missing fails the test (state the hart lacks
  must have a read-only-zero bit).
- **Causes** follow the HS-qualified rule of `hypervisor.adoc`: blocked by `mstateen`, illegal-instruction in every
  mode below M (also VS/VU); allowed by `mstateen` but blocked by `hstateen` or `sstateen`, or hypervisor/VS state
  reached with V=1, virtual-instruction; U-mode, illegal-instruction. Each trap is checked for xepc, xtval (0 or the
  instruction bits) and the mode it came from.
- **Gating sweeps** (`mstateen0_*_op`, `mstateen_bit_63_op`, `stateen0_jvt_op`, `mstateen_bit_correspondence`)
  boot to S, set the bit to 1, 0, 1 through T-SBI and read the state from S, U, VS and VU:
  `sstateen0`/`hstateen0`/`hstateen0h` (SE0), `senvcfg`/`henvcfg`/`henvcfgh` (ENVCFG), `stopei` (IMSIC), `stopi`
  and `hvictl` (AIA), `scontext`/`hcontext` (CONTEXT), `hedelegh` (P1P13, RV32),
  `sstateenN`/`hstateenN`/`hstateenNh` (bit 63 of each `mstateenN`), `jvt` (JVT at all three levels).
  `stateen_illegal_state_access` runs all eight CSR instruction forms on `senvcfg` in every mode and enable state.
- **Crossing.** `mstateen0_enc_img` clears one defined bit at a time and checks that only that bit's state changes
  (11 pieces of state). `mstateen0_se0_op` checks SE0 does not gate `sstateen1-3`/`hstateen1-3`/`senvcfg`, and
  `mstateen0_envcfg_op` that ENVCFG does not gate `sstateen0`. `stateen0_c_op` checks the C bits never open standard
  state.
- **Structure** tests boot to M (require `Sm`) and read every stateen CSR directly: existence and width
  (`mstateen_rv64_csrs`, `stateen_rv32_upper_bits_csrs`, including illegal-instruction for the high halves on RV64),
  WARL behavior with random patterns (`stateen_warl_access`), reserved and unimplemented-state bits
  (`stateen_reserved_roz_Sm`, `stateen_unimplemented_state_roz`, using only the `*_SUPPORTED` macros), masking of
  `hstateen`/`sstateen` by `mstateen` (whole register and one bit at a time, with field-modulation re-writes),
  read-only-one constraints, bit 63, and the FCSR bit with `misa.F`.
- **M-mode is not gated** (`stateen_op_Sm`): every controlled CSR read in M-mode has the same outcome with
  `mstateen0-3` = 0 as with the boot values.
- Every test saves the stateen CSRs it changes and restores them (the framework boot enables all standard state).
- **Mutation check.** 28 mutants in `gen_Smstateen.py` (`Smstateen:<name>`), e.g. hstateen gating HS-mode, sstateen
  ignored for U/VU, virtual- and illegal-instruction swapped, unmasked lower-level bits, writable reserved or
  unimplemented-state bits, read-only hstateen bit 63, M-mode gated, C opening all state, bits at the wrong
  position. Each makes at least one test fail on Sail.

Rules not tested here:

- **Other suites.** `mstateen0_csrind_op`, `Sscsrind_csrs_access_control` (Smcsrind) and `hstateen0_csrind_op`,
  `hypervisor_impl_csrs_access_control` (Sscsrind); the CTR rules `mstateen_ctr*`, `hstateen_ctr`, `hstateen_vs`,
  `hstateen0_ctr0_v1_op` (Ssctr). `siselect` and `sctrctl` still appear here as positions in `mstateen0_enc_img`.
- **Ssstateen** holds the S-level rules (`sstateen_*`, `hstateen_*` except the read-only-one rule
  `hstateen_ro1_bits`, which needs `mstateen`, and `stateen_op`/`stateen_reserved_roz`, whose M-mode parts are the
  `_Sm` files here).
- `stateen_implicit_state_update`: whether an implicit update of disabled state traps is left open ("may or may not");
  each extension must say, so there is nothing to check here.
- `mstateen_zero_initialization`: the framework boot (`tests/env/rvtest_setup.h`) writes `mstateen0-3` before any test
  code runs, so the reset value cannot be observed. It needs a framework hook ahead of the boot writes.
- `Sha_dep` (an extension-dependency list) is not behavior.
- **Not exercised by the standard configurations:** no Sail, Spike, Whisper, QEMU or Imperas configuration in
  `config/` has Zcmt or Zfinx, so there `jvt` and `fcsr`-on-x-registers do not exist and only the read-only-zero
  side of the JVT/FCSR paths runs. The FCSR paths (and the user-state mutants) were exercised on scratch Zfinx
  configurations of Sail and Spike (FCSR and C bits writable); Zcmt paths remain unexercised. Sail clears
  `misa.F` on request, so `stateen0_fcsr0_misa_f0_illegal_fpu_instr` runs its illegal-FP-instruction cases there.

Subtleties:

- VS/VU accesses blocked by `mstateen` raise illegal-instruction, not virtual-instruction, because they are not
  HS-qualified ([#1528](https://github.com/riscv/riscv-isa-manual/issues/1528)). With P1P13 = 0, `hedelegh` does not
  exist and the same rule applies ([#3459](https://github.com/riscv/riscv-isa-manual/issues/3459)). Writes to read-only
  CSRs are illegal in every mode ([#1512](https://github.com/riscv/riscv-isa-manual/issues/1512)), so the sweeps use
  reads.
- A VS-mode `stopei` access also needs `hstatus.VGEIN` to name a guest interrupt file; with the boot's VGEIN = 0 it
  raises virtual-instruction whatever `hstateen0.IMSIC` is.
- When an `mstateen` bit returns to 1, the matching `hstateen`/`sstateen` bit takes an UNSPECIFIED legal value (field
  modulation, [#1636](https://github.com/riscv/riscv-isa-manual/issues/1636)); tests re-read or rewrite it.
- With `mstateenN[63]` = 0, `hstateenN`/`sstateenN` cannot be read from S-mode; the sweeps read them only while the bit
  is 1.
- `mstateen_bit_63_roz` says when bit 63 _may_ be read-only zero; `stateen_unimplemented_state_roz` would require it
  without S (no `sstateen`/`hstateen` exist). Sail, Spike and Whisper keep it writable on M+U harts, so the test
  does not check SE0 (or `mstateen1-3[63]`) without S. A spec clarification would settle it.
- `hstatus.VGEIN` is WLRL; `hstateen0_imsic_op` writes 1 only when `hgeie` bit 1 is writable (GEILEN >= 1).
- The C bit is for custom state ([#2300](https://github.com/riscv/riscv-isa-manual/issues/2300)); no standard state may
  depend on it.
- Known DUT bugs in this area: QEMU makes P1P13 writable where `hedelegh` does not exist
  ([qemu#4495](https://gitlab.com/qemu-project/qemu/-/work_items/4495)) and ENVCFG/CSRIND/AIA/IMSIC writable without S
  ([qemu#4655](https://gitlab.com/qemu-project/qemu/-/work_items/4655)); on RV32 a write to `mstateen0` clears
  `mstateen0h.ENVCFG` ([qemu#4611](https://gitlab.com/qemu-project/qemu/-/issues/4611)). Imperas let P1P13 be written
  on RV64 and kept `hstateen` bit 63 read-only; both are fixed in the engineering build. Whisper RV32 raises
  virtual-instruction for VS-mode `siselect` with `hstateen0h.CSRIND` = 1 ([whisper#237](https://github.com/tenstorrent/whisper/issues/237)). With Zfinx, Sail raises
  illegal- instead of virtual-instruction for `fcsr` blocked by `hstateen0`/`sstateen0` from VS/VU ([sail-riscv#2089](https://github.com/riscv/sail-riscv/issues/2089)).
