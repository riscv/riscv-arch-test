# Svade: rule-derived tests

Generated by `tests_ai/gen/gen_Sv.py` with the other supervisor virtual-memory suites. The shared mechanics (page
tables built at run time, user alias, fence conventions) are described in [../Sv/README.md](../Sv/README.md).

## How the extension is tested

`Svade_access_ad_bit_clear` clears `menvcfg.ADUE` (through T-SBI; it is read-only 0 without Svadu), then checks:

- S- and U-mode loads, stores and fetches to an A=0 page, and stores to a D=0 page, raise page faults;
- the PTE is unchanged after the fault, and the store does not write;
- loads and fetches of A=1, D=0 pages succeed without setting D;
- an A=0 superpage leaf faults.

## Rules not tested here

None. `pte_a_def`/`pte_d_def` (tests_ai/Sv) accept either scheme. The ADUE switch is in tests_ai/Svadu.

## Subtleties

- **Svadu configurations.** On a hart with both Svade and Svadu, ADUE=0 selects Svade. ADUE must therefore be cleared
  first ([#3450](https://github.com/riscv/riscv-isa-manual/issues/3450)).
