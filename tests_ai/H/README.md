# H: rule-derived tests for the hypervisor extension

One test per `norm:` rule in `src/priv/hypervisor.adoc`. Generated by `tests_ai/gen/gen_H.py`, which collects the area
modules `gen/h_*.py`:

- `h_csr`: CSR access from every mode, and VS CSR substitution.
- `h_misc`: CSR fields, and V=0/V=1 isolation.
- `h_virt`: trap controls, hypervisor instructions, FS/VS, cache-block enables.
- `h_ctr`: counters and `htimedelta`.
- `h_trap`: delegation, trap CSR writes, SRET/MRET, trap values.
- `h_int`: interrupts.
- `h_hlsv`: HLV/HLVX/HSV and MPRV.
- `h_gstage`: two-stage translation and fences.

Shared helpers are in `gen/hlib.py` (CSR table, hypervisor instruction encodings, trap windows) and `gen/hmem.py` (page
tables, memory-fault checks).

## How the extension is tested

- **Modes.** Tests boot to HS-mode and enter U, VS and VU with `sret` (or a T-SBI GOTO where `sret` itself is under
  test or trapping). M-level CSRs are reached through T-SBI. Rules that need M-mode trap handling, `medeleg`/`mideleg`
  writes, MRET, MPRV or the M-level trap CSRs are `<rule>_Sm.S` files that boot to M and require `Sm`, so RVA23 drops them.
  When only part of a rule is M-level, the rest is also in an S-boot `<rule>.S`.
- **Encodings.** CSRs are named by number, and hypervisor, CBO, FP and vector instructions are `.word` encodings. MARCH
  stays `rv${XLEN}i_zicsr_zifencei`, and the encodings are also the legal xtval values.
- **Traps.** Every trap is checked in the trap log:
  - the number of traps, the cause and xepc;
  - xtval: 0 or the instruction bits for illegal and virtual instruction, 0 or the address for memory faults;
  - htval/mtval2 and htinst/mtinst;
  - GVA, SPV, SPVP and MPV;
  - the mode the trap came from, and the handler mode.

  Before each trap, the fields the trap must write are preset to the opposite of their expected value.

- **HS-qualified versus virtual instruction.** Every H and VS CSR, and the supervisor and M-level CSRs, are accessed
  from HS, VS, VU and U over all eight CSR instruction forms; rs1=x0 and uimm=0 are reads. Instructions that HS-mode
  could not execute raise illegal-instruction from VS/VU, for example writes to read-only CSRs, MRET, and RV64
  high-half addresses. mstatus.TVM/TSR do not change the VS/VU outcome.
- **Trap controls.** VTSR, VTW, VTVM, TSR, TVM and TW are swept on and off, with negative dependencies: V-bits do not
  affect HS-mode, and TVM/TSR do not affect VS-mode. A WFI that could legally wait forever gets a pending,
  locally enabled, globally disabled interrupt as a wake-up source.
- **Counters and enables.** Enable bits in mcounteren, hcounteren, scounteren and the envcfg CSRs are WARL. Each case
  reads back what the hart holds and expects the outcome for that value (`TestFile.either`).
- **Interrupts.** Sources are hvip, sip.SSIP, mip.STIP/SEIP (T-SBI), Sscofpmf LCOFI and platform guest interrupts.
  Several pending interrupts are taken in order and read back from the trap log. Each alias (vsip/vsie with
  hip/hie/hvip, mip/mie with hip/hie) is checked in both directions with single-bit writes.
- **Memory.** Most translation tests issue HLV/HLVX/HSV from HS-mode, so only the access under test is translated.
  Tests that need guest execution identity-map the test image in both stages. G-stage modes are probed by writing
  hgatp. x4 roots are 16 KiB, and RV32 reaches GPAs above 4 GiB through 22-bit Sv32 PPNs. htval must match the exact
  stval address, and htinst must be a pseudoinstruction whenever htval is nonzero on an implicit VS-stage access.
- **Mutation check.** Each area module has a `MUTANTS` dict. `tests_ai/run_mutants.sh <area>: <config>` regenerates
  the suite once per mutant and requires a failure. Every mutant fails a test on Sail.

## Rules not tested, or only partly

- **Definitions or permissions:**
  - `hsxlen`, `vsxlen`: definitions.
  - `H_trap_xtinst_zero_ok`: a permission; zero is accepted wherever the table allows it.
  - `vsxl_ro`, `hstatus_vgein_acc`: permissive; the legal values are what is checked.
- **Not observable:**
  - `vs_stage_speculative_a_bit`: speculation.
  - `henvcfg_fiom_op`, `henvcfg_fiom_order`: I/O-versus-memory ordering on one hart.
  - `hgeip_bit_op`: needs a multi-source interrupt controller.
  - `sfence_vma_v0`: over-flushing is legal.
  - `cbo-inval_h_mode_enabled_op`: catches a discarding invalidate only on a hart with caches.
  - Fence "without a fence" cases accept old or new translations, so they catch a missing flush only on harts that
    cache translations.
- **XLEN changes:**
  - `hstatus_vsxl_32`: RV32 has no VSXL.
  - `hstatus_vsxl_change`: needs HSXLEN to change.
  - `hstatus_hupmm_rv32_access`: RV32 hstatus has no HUPMM.
  - `hstatus_vsxl_op`, `vsstatus_uxl_op`: VS and VU are not run at XLEN=32, because narrowing the pc of code
    above 2^31 depends on where the image is linked. The WARL encodings are tested.
- **Partial:**
  - `H_exception_priority`: only illegal/virtual instruction over misaligned and access faults, for HLV/HSV.
  - `H_trans_cache`: CBO.ZERO access faults only.
  - `H_tinst_addr_offset`: nonzero offsets come from misaligned LR/SC only.
  - `hfence-vvma_mode`, `hfence-gvma_op`: validity here; ordering in the fence tests.
  - `hgatp_root_pt_sz_align`: the upper 12 KiB of an aligned root is used; a misaligned root is a software error.
  - `hstatus_vsbe_*`, `vsstatus_ube`: big-endian paths run only where VSBE/UBE are writable.
  - `misa_H_op`: misa.H is only round-tripped. The framework's M handler reads mtval2/mtinst, so no trap can be taken
    while H is disabled.
  - `H_vscsrs_v1`: sepc/scause/stval retention cannot be checked, because the trap that ends each VS-mode window
    rewrites them.
  - `scontext` (in `H_scsrs_nomatch`): whether it exists is a parameter.
  - Guest external interrupts (`hgeip_hgeie_fields`, `hip_sgeip_sgeie_acc_op`, `hgeie_op`, `hstatus_vgein_op`,
    `hstatus_vgein_zero`, parts of `hip_vseip_vseie_op` and `hsint_priority`): run only where the framework can
    raise them (`RVTEST_SGEI_INTR_IMPL`); GEILEN is still probed at run time. Otherwise only hgeip = 0 is checked.
  - VSEI vectored entry: the trap log's vector field cannot represent vector 9 on RV64.
- **Elsewhere:**
  - The vstimecmp source of VSTIP and the hcounteren.TM gate on vstimecmp are tested in the Sstc suite.
- **Framework limits:**
  - The T-SBI CSR table has no `mtval`, `mtval2`, `mtinst`, `mideleg` or `mstatush`, so those rules are `_Sm`
    files, and RV32 `hstatus_vsbe_acc` cannot compare with mstatus.SBE.
  - The trap log holds four entries, so interrupt-priority chains are checked in overlapping groups of at most
    four.

## Subtleties

- **HS-qualified.** HS-qualified assumes mstatus.TVM=0 and TSR=0, so with TVM=1 a VS-mode hgatp access still raises
  virtual-instruction ([#1231](https://github.com/riscv/riscv-isa-manual/issues/1231)). Writes to read-only CSRs are
  not HS-qualified, so they raise illegal-instruction from VS/VU
  ([#796](https://github.com/riscv/riscv-isa-manual/issues/796)).
- **xtval on a virtual-instruction trap.** stval is written "the same as for an illegal-instruction trap", but the
  platform may write the instruction bits for some events and 0 for others (norm:stval, "depending on the underlying
  event"). So `H_virtinst_xtval` checks each trap for 0 or the instruction bits, and does not require a VU-mode
  virtual trap and a U-mode illegal trap of the same encoding to write equal values.
- **WFI.** VTSR and VTVM trap at once; VTW traps only after a bounded wait
  ([#1695](https://github.com/riscv/riscv-isa-manual/issues/1695)).
- **hedeleg.** Bits 18 and 19 must be writable even without the extensions that raise them
  ([#3347](https://github.com/riscv/riscv-isa-manual/issues/3347)). The reserved high bits are read-only zero
  ([#2191](https://github.com/riscv/riscv-isa-manual/issues/2191)).
- **GVA.**
  - HLV/HLVX/HSV faults, and MPRV accesses with MPV=1, always set GVA
    ([#2695](https://github.com/riscv/riscv-isa-manual/issues/2695)).
  - For breakpoints and misaligned accesses ([#672](https://github.com/riscv/riscv-isa-manual/issues/672),
    [#673](https://github.com/riscv/riscv-isa-manual/issues/673)), GVA must be 1 when xtval is nonzero; a zero
    xtval leaves GVA unconstrained.
- **HLVX.** HLVX faults as a load, and its execute check ignores R. MXR never makes a read-only page executable
  ([#682](https://github.com/riscv/riscv-isa-manual/issues/682)). vsstatus.SUM applies
  ([#1480](https://github.com/riscv/riscv-isa-manual/issues/1480)), and the transformed HLVX keeps bits 24:20 = 00011
  ([#1286](https://github.com/riscv/riscv-isa-manual/issues/1286)).
- **Implicit-access guest-page faults.** A guest-page fault on an implicit VS-stage access is reported for the original
  access type: an HSV gives cause 23 even though the failing access was the PTE read.
- **Framework state.**
  - sscratch, vsscratch, stvec and vstvec hold the framework's trap state. VS-mode substitution tests write them only
    with HS-mode's own value, so a write that wrongly lands in the HS CSR is still caught.
  - An `sret` into VS or VU, and a T-SBI return to HS, copy SPIE into HS-mode's SIE. Interrupt windows clear SIE and
    SPIE first.

## Model bugs found by this suite

- **Whisper:**
  - [whisper#227](https://github.com/tenstorrent/whisper/issues/227): with TVM=1, a VS/VU write of hgatp/satp raises
    illegal- instead of virtual-instruction.
  - [whisper#228](https://github.com/tenstorrent/whisper/issues/228): SRET does not clear vsstatus.SDT.
  - [whisper#229](https://github.com/tenstorrent/whisper/issues/229): HFENCE uses all of rs2 as the VMID/ASID.
    Ignoring bits above VMIDMAX/ASIDMAX is only recommended ("should"), so the tests accept either outcome there;
    the mandatory part (bits MAX-1:LEN) runs only on harts with LEN < MAX.
- **Spike:** [riscv-isa-sim#2531](https://github.com/riscv-software-src/riscv-isa-sim/issues/2531): hip.VSEIP stays
  set after VGEIN changes to 0.
- **QEMU, new:**
  - [qemu#4812](https://gitlab.com/qemu-project/qemu/-/work_items/4812): VS-mode FP/vector CSR writes do not dirty
    sstatus.FS/VS.
  - [qemu#4813](https://gitlab.com/qemu-project/qemu/-/work_items/4813): a VS ebreak leaves hstatus.GVA=0.
  - [qemu#4814](https://gitlab.com/qemu-project/qemu/-/work_items/4814): hideleg bits 63:16 are writable.
  - [qemu#4815](https://gitlab.com/qemu-project/qemu/-/work_items/4815): HLV/HSV ignore henvcfg.ADUE/PBMTE.
