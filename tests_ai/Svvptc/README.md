# Svvptc: rule-derived tests for PTEs made valid without a fence

One test for the only `norm:` rule in `src/priv/svvptc.adoc`. Generated by `tests_ai/gen/gen_Sx.py`. Mutant:
`Sx:vptc_never`.

## How the extension is tested

- **Method.** Each case first accesses a page whose PTE has V=0, which raises a page fault and may cache the
  invalid entry. It then stores V=1 with no SFENCE.VMA or HFENCE, and retries the access up to 500 times in a window
  that permits those faults. The access must succeed by the last try, and only the expected fault may occur in
  between.
- **Cases**, under Sv39 or Sv32 (probed):
  - a leaf PTE and a non-leaf PTE (the pointer to the leaf table);
  - a load, a fetch and a store;
  - a U-mode load, with the retry loop running in U-mode;
  - with H, a VS-stage and a G-stage leaf, seen through HLV.W.

## Rules not tested here, or only partly

- **The bound.** The rule promises visibility "within a bounded timeframe" but gives no bound. A hart that needs
  more than 500 retries cannot be told apart from one that never sees the store.
- **Not observable:** visibility to other harts, and whether the store is seen earlier than required.
- **Valid to invalid.** Svvptc says nothing about V going from 1 to 0, so SFENCE.VMA is still required there.

## Subtleties

- **H.** The rule says "PTEs" without naming a stage, so VS-stage and G-stage PTEs are treated the same, and no
  HFENCE is used. No issue settles this.

- cvw cached invalid PTEs until [cvw#1974](https://github.com/openhwfoundation/cvw/pull/1974), which is the bug
  this test is built to catch.
